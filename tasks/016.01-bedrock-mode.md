## Bedrock Mode for Claude and Codex

Part of epic 016. heinzel gets a third credential mode, Bedrock: Claude Code and the Codex it calls both use Amazon Bedrock with heinzel's AWS credentials, so no Anthropic or OpenAI key is needed.

### Acceptance Criteria

- **Selecting it.** `CLAUDE_CODE_USE_BEDROCK=1` turns Bedrock mode on. It then needs these settings:
  - `AWS_REGION`, required.
  - `ANTHROPIC_MODEL`, required: a Bedrock model or inference-profile id.
  - `CODEX_BEDROCK_MODEL`, required.
  - `ANTHROPIC_SMALL_FAST_MODEL`, which defaults to `ANTHROPIC_MODEL`, so the child never calls a model the role doesn't grant.
  - `CODEX_BEDROCK_REGION`, which defaults to `AWS_REGION`.

  A missing setting, or any of `ANTHROPIC_API_KEY`, `CLAUDE_CODE_OAUTH_TOKEN` or `OPENAI_API_KEY` being set, is a config error naming the variable. Outside Bedrock mode, config behaves exactly as today.
- **Credentials.** At the start of each run, heinzel resolves AWS credentials through the AWS SDK for Go's default chain (env, profile, ECS task role). It passes them to the child as `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` and `AWS_SESSION_TOKEN`. The child never needs heinzel's HOME or a credential endpoint. Credentials that would expire within `INVESTIGATION_TIMEOUT` are refreshed first. If freshly fetched credentials still expire too soon, the run fails as stage `claude` without starting the child, and the reason says so. Credentials without an expiry pass.
- **Claude.** The child runs Claude Code against Bedrock with the configured model. It keeps every isolation flag of API-key mode, `--bare` included, if `--bare` still sends Bedrock requests. Check that without an AWS account: use dummy credentials, point `ANTHROPIC_BEDROCK_BASE_URL` at a local stub, and see whether a SigV4-signed request arrives. If none does, use OAuth mode's flags and say why in the docs.
- **Codex.** Before each run, heinzel writes a fresh Codex config into the run's child HOME. It selects the `amazon-bedrock` provider with the Codex model and region.
- **Sandbox network.** In Bedrock mode, sandboxed commands can reach exactly the Bedrock hosts Codex uses for its region, checked against the Codex provider docs, and not `api.openai.com`.
- **Child env.** In Bedrock mode the child's env is exactly:
  - `PATH`, `HOME` and `CLAUDE_CONFIG_DIR`;
  - `CLAUDE_CODE_USE_BEDROCK`, `AWS_REGION`, `ANTHROPIC_MODEL` and `ANTHROPIC_SMALL_FAST_MODEL`;
  - `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`, plus `AWS_SESSION_TOKEN` only when the credentials have one.

  docs/event-model.md and the command test list it.
- **AWS needs.** docs/event-model.md lists the exact IAM actions, resource ARNs and hosts that Claude Code and Codex need in Bedrock mode, checked against both tools' docs. 016.03 grants exactly that.
- **System test.** `make system-test` also runs in Bedrock mode when the env selects it, with AWS credentials instead of the two key variables.
- **Docs.** docs/event-model.md describes the mode as it does the other two. Under accepted exposure it notes that the child can read the AWS credentials, so the role must be scoped to Bedrock invoke only.

### Notes

- No AWS credentials may be available while implementing. Then unit and e2e tests carry the proof, and the real Bedrock run is left to the user.
