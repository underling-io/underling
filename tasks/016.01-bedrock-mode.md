## Bedrock Mode for Claude and Codex

Part of epic 016. heinzel gets a third credential mode, Bedrock: Claude Code and the Codex it calls both use Amazon Bedrock with heinzel's AWS credentials, so no Anthropic or OpenAI key is needed.

### Acceptance Criteria

- **Selecting it.** `CLAUDE_CODE_USE_BEDROCK=1` turns Bedrock mode on. It then needs these settings:
  - `AWS_REGION`, required.
  - `ANTHROPIC_MODEL`, required: a Bedrock model or inference-profile id.
  - `CODEX_BEDROCK_MODEL`, required.
  - `ANTHROPIC_SMALL_FAST_MODEL`, which defaults to `ANTHROPIC_MODEL`, so the child never calls a model the role doesn't grant.
  - `CODEX_BEDROCK_REGION`, which defaults to `AWS_REGION`.

  A missing setting, or any of `ANTHROPIC_API_KEY`, `CLAUDE_CODE_OAUTH_TOKEN` or `OPENAI_API_KEY` being set, is a config error naming the variable. Outside Bedrock mode, config behaves exactly as today.
- **Credentials.** At the start of each run, heinzel resolves AWS credentials through the AWS SDK for Go's default chain (env, profile, ECS task role). It passes them to the child as `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` and `AWS_SESSION_TOKEN`. The child never needs heinzel's HOME or a credential endpoint. Credentials that would expire within `INVESTIGATION_TIMEOUT` are refreshed first. If freshly fetched credentials still expire too soon, the run fails as stage `claude` without starting the child, and the reason says so. Credentials without an expiry pass.
- **Claude.** The child runs Claude Code against Bedrock with the configured model. It keeps every isolation flag of API-key mode, `--bare` included, if `--bare` still sends Bedrock requests. Check that without an AWS account: use dummy credentials, point `ANTHROPIC_BEDROCK_BASE_URL` at a local stub, and see whether a SigV4-signed request arrives. If none does, use OAuth mode's flags and say why in the docs.
- **Codex.** Before each run, heinzel writes a fresh Codex config into the run's child HOME. It selects the `amazon-bedrock` provider with the Codex model and region.
- **Sandbox network.** In Bedrock mode, sandboxed commands can reach exactly the Bedrock hosts Codex uses for its region, checked against the Codex provider docs, and not `api.openai.com`.
- **Child env.** In Bedrock mode the child's env is exactly:
  - `PATH`, `HOME` and `CLAUDE_CONFIG_DIR`;
  - `CLAUDE_CODE_USE_BEDROCK`, `AWS_REGION`, `ANTHROPIC_MODEL` and `ANTHROPIC_SMALL_FAST_MODEL`;
  - `ANTHROPIC_DEFAULT_OPUS_MODEL`, `ANTHROPIC_DEFAULT_SONNET_MODEL` and `ANTHROPIC_DEFAULT_FABLE_MODEL` (all `ANTHROPIC_MODEL`) and `ANTHROPIC_DEFAULT_HAIKU_MODEL` (`ANTHROPIC_SMALL_FAST_MODEL`);
  - `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`, plus `AWS_SESSION_TOKEN` only when the credentials have one.

  docs/event-model.md and the command test list it.
- **AWS needs.** docs/event-model.md lists the exact IAM actions, resource ARNs and hosts that Claude Code and Codex need in Bedrock mode, checked against both tools' docs. 016.03 grants exactly that.
- **System test.** `make system-test` also runs in Bedrock mode when the env selects it, with AWS credentials instead of the two key variables.
- **Docs.** docs/event-model.md describes the mode as it does the other two. Under accepted exposure it notes that the child can read the AWS credentials, so the role must be scoped to Bedrock invoke only.

### Notes

- No AWS credentials may be available while implementing. Then unit and e2e tests carry the proof, and the real Bedrock run is left to the user.

## Implementation Plan

### TLDR

All changes sit in the `investigatesentryissue` slice:
- **Mode.** `CLAUDE_CODE_USE_BEDROCK=1` turns Bedrock mode on.
- **Credentials.** heinzel resolves AWS credentials per run through an aws-sdk-go-v2 credentials cache. The cache's expiry window equals `INVESTIGATION_TIMEOUT`, so near-expiry credentials are refetched automatically.
- **Child.** heinzel passes the credentials to the child as env vars and writes a fresh Codex `config.toml` (the `amazon-bedrock` provider) into the child's HOME.
- **Sandbox.** It allows only `bedrock-mantle.<codex region>.api.aws`. Claude Code keeps `--bare`.
- **Docs.** They gain an exact "AWS needs" section, which 016.03 grants 1:1.

### Steps

1. **Config (`config.go`).**
   - Only `CLAUDE_CODE_USE_BEDROCK=1` selects Bedrock. Unset or `""` means off, and then every Bedrock var is ignored. Any other value is an error naming the variable.
   - In Bedrock mode:
     - `AWS_REGION`, `ANTHROPIC_MODEL` and `CODEX_BEDROCK_MODEL` are required.
     - `ANTHROPIC_SMALL_FAST_MODEL` defaults to `ANTHROPIC_MODEL`.
     - `CODEX_BEDROCK_REGION` defaults to `AWS_REGION`.
     - A non-empty `ANTHROPIC_API_KEY`, `CLAUDE_CODE_OAUTH_TOKEN` or `OPENAI_API_KEY` is an error naming that variable.
     - The `OPENAI_API_KEY` requirement drops.
   - Validate the values, because they end up in a hostname and in TOML:
     - Both regions must have the AWS region shape: lowercase, hyphenated, ending in a digit.
     - Model ids must be non-blank and use only `[A-Za-z0-9._:/-]`.
   - Errors are joined as today. Existing config tests pass untouched.
2. **Credentials seam (cross-package contract).**
   - `Params` gains an optional `aws.CredentialsProvider`, a raw provider rather than a cache. The `init()` factory passes nil.
   - In Bedrock mode:
     - With nil, `New` calls `config.LoadDefaultConfig(WithRegion(AWS_REGION), WithCredentialsCacheOptions(...))`.
     - With a provider set, it wraps it once in `aws.NewCredentialsCache` with the same options.
     - The options are `ExpiryWindow = INVESTIGATION_TIMEOUT` and `ExpiryWindowJitterFrac = 0`.
     - A load error is a startup config error.
   - Add `github.com/aws/aws-sdk-go-v2/{aws,config}`. It's pure Go, so `CGO_ENABLED=0` still builds.
3. **Per-run check, before the child starts.**
   - `Retrieve` with a bounded context of about a minute.
   - The cache shifts `Expires` earlier by the window and refetches anything inside it. So freshly fetched credentials that still expire too soon show up as `creds.Expired()` on the result. The reason gives the real expiry (`Expires + timeout`) and the timeout.
   - `CanExpire == false` passes.
   - Retrieve errors and expiry failures are formatted as text, not wrapped with `%w`. An SDK or net error with `Timeout() == true` would otherwise satisfy `timedOut()` and land as stage `timeout`, not `claude`.
   - The child doesn't start, and the run dir is still removed.
4. **Codex config.** In each Bedrock run, after the workspace exists and before the child starts, write `<child HOME>/.codex/config.toml` (dir 0700, file 0600) with a TOML encoder. It holds `model_provider = "amazon-bedrock"`, `model = <CODEX_BEDROCK_MODEL>`, and `[model_providers.amazon-bedrock.aws] region = <CODEX_BEDROCK_REGION>`. The region has to be in the file because the child's `AWS_REGION` is Claude's, and Codex reads the file's region first. A write failure fails the run as stage `claude`. In other modes, write nothing.
5. **`claude.Command`.**
   - `claude.Config` gains an optional Bedrock block: region, model, small-fast model, Codex region and the per-run credentials. API-key and OAuth argv, env and settings stay byte-identical.
   - In Bedrock mode:
     - The argv is API-key mode's, with `--bare`.
     - The env is exactly `PATH`, `HOME`, `CLAUDE_CONFIG_DIR`, `CLAUDE_CODE_USE_BEDROCK=1`, `AWS_REGION`, `ANTHROPIC_MODEL`, `ANTHROPIC_SMALL_FAST_MODEL`, `ANTHROPIC_DEFAULT_{OPUS,SONNET,FABLE,HAIKU}_MODEL` (added in review), `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`, plus `AWS_SESSION_TOKEN` only when it's non-empty.
     - `sandbox.network.allowedDomains` is exactly `["bedrock-mantle.<CODEX_BEDROCK_REGION>.api.aws"]`.
6. **e2e (`e2e_test.go`, with a fake provider through `Params` and the fake claude).**
   - The child's exact env and the `config.toml` content, as the child saw them.
   - Near-expiry credentials are refetched once, and the child gets the second set.
   - Still too soon: Failed stage `claude`, with zero claude calls.
   - Non-expiring credentials give no `AWS_SESSION_TOKEN`.
   - A provider error gives stage `claude`.
7. **Empirical stub checks.** They need loopback binding, which the sandbox blocks, so run them outside it and record the results in the docs:
   - **(a) `--bare` against a stub.** A panelist already ran this on claude 2.1.317 with dummy creds and `ANTHROPIC_BEDROCK_BASE_URL` pointed at a stub. It got SigV4 `GET /inference-profiles` and `POST /model/<id>/invoke(-with-response-stream)`. Re-run it once on the pinned claude version.
   - **(b) Startup model probes.** Claude Code also called `/invoke` on about ten other models at startup. Re-run with a stub that answers 403 `AccessDeniedException` for every model but the configured one:
     - If the run still reaches the configured model, document the probes as expected denials and grant nothing extra.
     - If they block the run, stop and report it as a Major finding.
   - **(c) Codex.** Run `codex exec` with the step-4 config plus a `base_url` stub override and dummy env creds. Confirm the SigV4 scope `<CODEX_BEDROCK_REGION>/bedrock-mantle` and the paths it calls; a call to `/models` adds `ListModels`/`GetModel` to the IAM list.
8. **docs/event-model.md.** Describe Bedrock mode as the other two modes are described:
   - **Config:** the config rows.
   - **Credentials:** they come from heinzel's own process env, profile or ECS endpoint, not from the slice's getenv. The per-run refresh and the expiry failure.
   - **Isolation:** the Bedrock env, the `allowedDomains` variant, the `config.toml` and the stub-check results.
   - **Accepted exposure:** the child can read the AWS credentials, so the role must be scoped to Bedrock invoke only.
   - **"AWS needs"** (new subsection):
     - **Claude Code, invoke:** `bedrock:InvokeModel` and `bedrock:InvokeModelWithResponseStream` on `ANTHROPIC_MODEL` and `ANTHROPIC_SMALL_FAST_MODEL`. An inference profile means its `inference-profile/<id>` ARN plus the foundation-model ARNs in every region it routes to; check the `global.` form against AWS docs. A foundation-model id means its foundation-model ARN.
     - **Claude Code, profile lookup:** `bedrock:ListInferenceProfiles` and `bedrock:GetInferenceProfile`, with resource types per the Service Authorization Reference.
     - **Claude Code, hosts:** `bedrock-runtime.<region>.amazonaws.com` and `bedrock.<region>.amazonaws.com`.
     - **Codex:** `bedrock-mantle:CreateInference` on `arn:aws:bedrock-mantle:<codex region>:<account>:project/*`, conditioned on `bedrock-mantle:Model`, plus whatever 7(c) shows. Host: `bedrock-mantle.<codex region>.api.aws`.
     - **Not granted:** no marketplace actions. Model access is a one-time account setup, not runtime.
9. **System test and Makefile.**
   - When `CLAUDE_CODE_USE_BEDROCK=1`:
     - require `AWS_REGION`, `ANTHROPIC_MODEL` and `CODEX_BEDROCK_MODEL`;
     - forward those and the two optional Bedrock vars;
     - forward whichever of `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN`, `AWS_PROFILE`, `AWS_CONFIG_FILE` and `AWS_SHARED_CREDENTIALS_FILE` are set;
     - never forward the three key vars.
   - Update the `system-test` comment.

### Notes

- `ANTHROPIC_SMALL_FAST_MODEL` is deprecated in favour of `ANTHROPIC_DEFAULT_HAIKU_MODEL` but still honoured. Keep it, as the AC names it, and say so in the docs.
- The AC's premise "never calls a model the role doesn't grant" doesn't hold: Claude Code probes other models at startup (7b). Record that in the implementation notes.
- Mantle has no cross-region inference, so `CODEX_BEDROCK_MODEL` is a plain regional id.
- help.openai.com returns 403 to WebFetch. Use learn.chatgpt.com/docs/amazon-bedrock for the Codex provider docs.
- Least verified: whether Codex needs anything beyond `CreateInference`. Only a real run settles it, so pass it to the user.

## Implementation Notes

### Stub checks (step 7)

All run on 2026-11-03, outside the sandbox (loopback binding), with dummy credentials, a fresh `HOME`/`CLAUDE_CONFIG_DIR`, `env -i`, and a local Python stub. No real credentials, no `~/.aws`, no traffic to AWS.

- **(a) `--bare` on Bedrock: passes.** On Claude Code 2.1.317, the local version (the docs now pin 2.1.317 and Codex 0.165.0, from the gap-check). With `ANTHROPIC_BEDROCK_BASE_URL` at the stub, the run sent SigV4-signed requests with scope `eu-central-1/bedrock` and `X-Amz-Security-Token`. It called `GET /inference-profiles?type=SYSTEM_DEFINED`, then `POST /model/<id>/invoke` probes, then `POST /model/<ANTHROPIC_MODEL>/invoke-with-response-stream`. Bedrock mode keeps `--bare`.
- **(b) Startup probes: they don't block the run.** The stub answered 403 `AccessDeniedException` for every model but the configured one. Claude Code probed 11 other models, all `eu.` geo profiles of other Opus, Sonnet and Haiku versions, so they follow `AWS_REGION`'s geo. It still sent the prompt to `ANTHROPIC_MODEL`. They are documented as expected denials, and nothing extra is granted. As the plan's Notes predicted, the AC premise that the child "never calls a model the role doesn't grant" doesn't hold. The child does call them, and they are refused.
- **(c) Codex 0.165.0: confirmed.**
  - With the generated config plus a `base_url` override, it made only `POST /openai/v1/responses` calls, signed with scope `<file region>/bedrock-mantle`, even though the env's `AWS_REGION` differed. There were no `/models` calls, so no `ListModels`/`GetModel` grant is needed.
  - Without the file's region, it used `AWS_REGION`. So the file region is needed.
  - A second run used the exact generated config (no `base_url`) with `HTTPS_PROXY` at the stub, which logged the CONNECT targets. Codex accepted the file and connected to `bedrock-mantle.<region>.api.aws:443`. It also tried `chatgpt.com:443`, `github.com:443` and `api.github.com:443`, which the sandbox's allowlist refuses in production. That is documented as expected denials.
- The scripts are in the session scratchpad (`stub/stub.py`, `run_claude.sh`, `run_codex*.sh`). They aren't committed.

### Deviations and decisions

- **Model aliases pinned (review fix).** The child env also carries `ANTHROPIC_DEFAULT_OPUS_MODEL`, `ANTHROPIC_DEFAULT_SONNET_MODEL` and `ANTHROPIC_DEFAULT_FABLE_MODEL` = `ANTHROPIC_MODEL` (`fable` added in the fix review: 2.1.317 also has that alias), and `ANTHROPIC_DEFAULT_HAIKU_MODEL` = `ANTHROPIC_SMALL_FAST_MODEL`; the Child env AC was amended to match. Claude Code 2.1.317 resolves the `opus`/`sonnet`/`haiku` aliases through these vars, not `ANTHROPIC_MODEL`, so a subagent with `model: sonnet` (the Codex plugin's `codex-rescue`) would otherwise call Claude Code's default Bedrock id, which the IAM role doesn't grant, and fail. Stub check (d) (`stub/run_alias.sh` in the scratchpad, dummy creds, an `--agents` definition with `model: sonnet` run via `--agent`): unpinned, requests went to `eu.anthropic.claude-sonnet-4-5-20250929-v1:0`; pinned, to the configured `global.anthropic.claude-sonnet-4-5-20250929-v1:0`. The stub can't return a real response, so it checks a main-thread agent's alias, not a spawned subagent's; both resolve through the same alias mapping.
- **Generated TOML** (go-toml/v2, now a direct dependency, previously indirect via gin). It uses single-quoted strings and an empty `[model_providers]` header before the subtables. It is valid TOML, and Codex accepted it (check (c)).
- **Codex providers.** The Codex Bedrock docs now list two providers: `amazon-bedrock` (Mantle, in-region) and `amazon-bedrock-runtime` (cross-region via bedrock-runtime). We use `amazon-bedrock` as the Locked Decision says. The docs page doesn't document `[model_providers.amazon-bedrock.aws] region`, but the stub check proves Codex honours it.
- **Config errors.** `CLAUDE_CODE_USE_BEDROCK` with a value other than `1`/empty is an error. An optional Bedrock var never reports "must be set": if `AWS_REGION` is missing, only `AWS_REGION` is named.
- **Docs.** A `#### Paths the child may not read` heading now separates the existing HOME/PATH paragraphs, which used to sit under Configuration, from the new `#### Bedrock mode` subsection. New subsections: Bedrock mode, AWS needs, Bedrock stub checks.
- **Refetch e2e test.** It uses the real clock and sleeps about 0.5s. The SDK credentials cache reads `time.Now` through an internal package, so a fake clock can't be injected. The fake provider stamps the first set's expiry at fetch time (timeout + 500ms), so the test doesn't depend on how fast the harness starts.
- **Default-chain e2e test.** `TestBedrockModeResolvesCredentialsThroughTheDefaultChain` exercises `Params.AWS == nil`. It points `AWS_CONFIG_FILE`/`AWS_SHARED_CREDENTIALS_FILE` at missing temp paths and takes credentials from `t.Setenv`, so it never reads `~/.aws`.
- **IAM facts** were checked against the AWS Service Authorization Reference (`list_bedrock-mantle`: `CreateInference` on `project`, condition key `bedrock-mantle:Model`) and the Bedrock user guide. The global-profile page says the region-less `arn:aws:bedrock:::foundation-model/<id>` is required. I couldn't read the Actions-table rows for `bedrock:ListInferenceProfiles`/`GetInferenceProfile`, so their resource scope (`inference-profile/*` vs `*`) follows AWS's own examples, not the reference table. 016.03 should confirm it (an `IAM policy simulator` run or a real call).
