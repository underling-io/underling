## Rust Foundation: Store, Runner, App, Wiring

Part of epic 011 (read its Locked Decisions). Add the Rust crate with the generic infrastructure the slices will run on: the event store, the event handler runner, the app (slice kinds, automatic wiring, run and shutdown), CLI flags and logging. No slices yet. The Go code stays untouched and keeps passing.

### Acceptance Criteria

- **Event store** (`redb`), with the semantics of `internal/eventstore`, covered by tests ported from `store_test.go`:
  - append several events to a stream at an expected version, returning the new version and position;
  - a version mismatch returns a conflict error naming the stream, its version and the expected one, and stores nothing;
  - positions are global and gapless across streams;
  - read after a position with a limit;
  - checkpoints by name, defaulting to 0;
  - subscribers are woken on append;
  - timestamps come from an injectable clock;
  - data survives a close and reopen.
- **Event handler runner**, with the semantics of `internal/eventhandler`, covered by tests ported from `runner_test.go`:
  - each handler has a name and handles one event at a time, in position order, starting after its checkpoint;
  - the checkpoint is saved after each event, so a restart resumes where it left off;
  - handlers run independently;
  - a store error stops that handler with a logged "event handler stopped" error;
  - stop waits for in-flight handling to finish and doesn't checkpoint an event it didn't handle.
- **App:**
  - **Slice kinds.** A state change is one HTTP route (method + path) and a handler built from the store. An automation is an event handler built from a cancellation token and the store. Factories take `Deps` (env lookup, logger) and may fail with a config error.
  - **Automatic wiring.** `build.rs` generates the slice list from the dirs under `src/slices/`. A test fails if a slice dir doesn't register.
  - **Run** serves the routes and runs the automations, then shuts down in the epic's order; the first error is returned. The "app started" and "app shutting down" log lines keep their Go fields.
  - **Tests** ported from `internal/app` cover the shutdown order and the automations' token being cancelled before the handlers stop. They use test slices registered in test code, not real ones.
- **Binary.**
  - The flags `--addr` (default `:8080`), `--data-dir` (`./data`) and `--shutdown-timeout` (`10s`).
  - `--help` exits 0. Invalid arguments log "invalid arguments" and exit 2. A failed slice build logs "invalid configuration" and exits 2.
  - SIGINT/SIGTERM shut down gracefully.
  - Logs are JSON on stderr.
- **Guard test.** Slices may use only the allowed `crate::` modules and their own sub-modules, per the epic. It's vacuous until slices exist, but it must catch a planted violation in a test fixture or by unit-testing the checker.

### Notes

- The Go tests are the spec. Port their scenarios, not their mechanics (no bind-port tests needed if an in-memory or ephemeral listener works; binding `127.0.0.1:0` is fine).
- `src/slices/` exists, with the generated wiring producing an empty list for now.
