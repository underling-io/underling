## Rust Foundation: Store, Runner, App, Wiring

Part of epic 011 (read its Locked Decisions). Add the Rust crate with the generic infrastructure the slices will run on: the event store, the event handler runner, the app (slice kinds, automatic wiring, run and shutdown), CLI flags and logging. No slices yet. The Go code stays untouched and keeps passing.

### Acceptance Criteria

- **Event store** (`redb`), with the semantics of `internal/eventstore`, covered by tests ported from `store_test.go`:
  - append several events to a stream at an expected version, returning the new version and position;
  - a version mismatch returns a conflict error naming the stream, its version and the expected one, and stores nothing;
  - positions are global and gapless across streams;
  - read after a position with a limit;
  - checkpoints by name, defaulting to 0;
  - subscribers are woken on append;
  - timestamps come from an injectable clock;
  - data survives a close and reopen.
- **Event handler runner**, with the semantics of `internal/eventhandler`, covered by tests ported from `runner_test.go`:
  - each handler has a name and handles one event at a time, in position order, starting after its checkpoint;
  - the checkpoint is saved after each event, so a restart resumes where it left off;
  - handlers run independently;
  - a store error stops that handler with a logged "event handler stopped" error;
  - stop waits for in-flight handling to finish and doesn't checkpoint an event it didn't handle.
- **App:**
  - **Slice kinds.** A state change is one HTTP route (method + path) and a handler built from the store. An automation is an event handler built from a cancellation token and the store. Factories take `Deps` (env lookup, logger) and may fail with a config error.
  - **Automatic wiring.** `build.rs` generates the slice list from the dirs under `src/slices/`. A test fails if a slice dir doesn't register.
  - **Run** serves the routes and runs the automations, then shuts down in the epic's order; the first error is returned. The "app started" and "app shutting down" log lines keep their Go fields.
  - **Tests** ported from `internal/app` cover the shutdown order and the automations' token being cancelled before the handlers stop. They use test slices registered in test code, not real ones.
- **Binary.**
  - The flags `--addr` (default `:8080`), `--data-dir` (`./data`) and `--shutdown-timeout` (`10s`).
  - `--help` exits 0. Invalid arguments log "invalid arguments" and exit 2. A failed slice build logs "invalid configuration" and exits 2.
  - SIGINT/SIGTERM shut down gracefully.
  - Logs are JSON on stderr.
- **Guard test.** Slices may use only the allowed `crate::` modules and their own sub-modules, per the epic. It's vacuous until slices exist, but it must catch a planted violation in a test fixture or by unit-testing the checker.

### Notes

- The Go tests are the spec. Port their scenarios, not their mechanics (no bind-port tests needed if an in-memory or ephemeral listener works; binding `127.0.0.1:0` is fine).
- `src/slices/` exists, with the generated wiring producing an empty list for now.

## Implementation Plan

### TLDR

Add one Cargo package at the repo root: `eventstore` (redb, sync API, explicit close), `eventhandler` (one tokio task per handler, async `handle`), `app` (slice kinds, `build`, `run`, `Config` via clap) and a thin `main`. A `build.rs` turns `src/slices/*/` into a generated module list plus a `FACTORIES` constant, and integration tests enforce the wiring and the import rule.

### Steps

1. **Crate skeleton.** `Cargo.toml` (edition 2024), `src/lib.rs` with `#![forbid(unsafe_code)]` and `#![warn(missing_docs)]`, `src/main.rs`, `target/` in `.gitignore`, `Cargo.lock` committed. Crates are the epic's (`tokio`, `tokio-util`, `axum`, `serde`/`serde_json`, `tracing`/`tracing-subscriber` with `json`, `clap` derive, `thiserror`, `redb`). Add `chrono` (serde) for timestamps, `humantime` for durations and `async-trait` for the handler trait. Dev-deps: `tempfile`, `reqwest` (no default features, plain HTTP), `syn` (full, visit) and `proc-macro2` for the guard. No `anyhow`, since `main` maps errors to exit codes itself.
2. **`eventstore`.** Locks these contracts:
   - The redb file is `<data-dir>/underling.redb` (a new name, so a leftover bbolt `underling.db` is never opened). Tables are `events` (u64 position → JSON `Event`), `streams` (stream id → u64 version) and `checkpoints` (name → u64 position). Port `TestPersistedLayout` as a unit test that reads the raw tables.
   - `Event { stream_id, version, position, event_type (JSON "type"), timestamp: DateTime<Utc>, payload: serde_json::Value }`, camelCase JSON. Timestamps are RFC 3339 with nanoseconds. `NewEvent { event_type, payload }`.
   - API: `Store::open(dir)` / `Store::open_with_clock(dir, clock)`; `append(stream, expected_version, &[NewEvent]) -> Appended { version, position }`; `read_after(position, limit)`; `checkpoint(name)`; `set_checkpoint(name, position)`; `subscribe() -> Subscription` (async wait); `close()`. The store is shared as `Arc<Store>`.
   - `Error` (thiserror) with a `Conflict { stream, actual, expected }` variant that names all three, plus `NoEvents`, `Closed`, and wrapped I/O, redb and decode errors.
   - `close()` really closes the redb file even while other `Arc`s exist, and later calls return `Closed`. This is load-bearing: after a forced HTTP shutdown a request task may still hold the store, and the app must still close it so a reopen works (Go's `TestShutdownCompletesWhenRequestOutlivesTimeout`).
   - Wake-ups go through a `tokio::sync::watch` channel, so they coalesce per subscriber, and a rejected append notifies nobody.
   - Port every `store_test.go` scenario, including the open-twice failure, the missing nested data dir, the empty append and 50 concurrent appends to a new stream admitting exactly one.
3. **`eventhandler`.** An `#[async_trait] Handler: Send` with `fn name(&self) -> &str` and `async fn handle(&mut self, event: Event)`. `Runner::start(Arc<Store>, Vec<Box<dyn Handler>>)` spawns one task per handler (with the current tracing dispatcher attached). `Runner::stop(self).await` logs "stopping event handlers", cancels, joins and returns the first error. The loop:
   - checks the stop signal before each event, never during `handle`;
   - checkpoints after each event;
   - reads in batches of 100;
   - waits on either a wake-up or stop.

   A store error ends that loop with an ERROR "event handler stopped" (fields `handler`, `error`). Port the `runner_test.go` scenarios. Add a test that one blocked handler doesn't hold up another, and one for the store error: close the store while a handler is mid-event, then release it, and check the log line and the error from `stop`.
4. **`app` slice kinds and build.**
   - `StateChange::new(method: MethodFilter, path, build)`, where `build: FnOnce(Arc<Store>) -> H` returns any axum handler. It is stored erased as a `MethodRouter`, with pub `method` and `path` fields.
   - `Automation::new(build)`, where `build: FnOnce(CancellationToken, Arc<Store>) -> impl Handler`.
   - `Deps<'a> { getenv: &'a dyn Fn(&str) -> Option<String> }`. There is no logger field: slices log through `tracing`.
   - `ConfigError = Box<dyn Error + Send + Sync>`, so a slice keeps its own typed error and `?` erases it.
   - `Factory` enum: `StateChange(fn(&Deps) -> Result<StateChange, ConfigError>)` | `Automation(...)`.
   - `build(&[Factory], &Deps) -> Result<Slices, ConfigError>` keeps list order within each kind, stops at the first error and returns it unchanged.
   - Port the four `registry_test.go` cases against a test factory list.
5. **`app::Config` and `app::run`.**
   - `Config` derives clap `Parser`: `--addr` `:8080`, `--data-dir` `./data`, `--shutdown-timeout` `10s` (parsed by humantime). Positional args are rejected. Port the `config_test.go` cases with `try_parse_from`.
   - `run(&Config, TcpListener, Slices, shutdown: CancellationToken) -> Result<(), app::Error>` opens the store and builds the router and automations. It logs "app started" (`addr` = the listener's local addr, `dataDir`) and serves until the token fires or serving fails. Then it logs "app shutting down" and runs the epic's four steps, each of them, returning the first error.
   - The HTTP drain is axum graceful shutdown under `shutdown_timeout`. On timeout it aborts the serve task and records an error.
   - Port the `app_test.go` and `automation_test.go` scenarios. Bind `127.0.0.1:0`, and use the "app shutting down" log line as the "shutdown began" sync point in place of the notifying listener.
6. **Wiring.**
   - The slice-dir rule lives in one file (`build/slice_dirs.rs`), used by `build.rs` and by the tests via `#[path]`. A slice dir is a direct child of `src/slices/` whose name doesn't start with `.` or `_`. It must hold `mod.rs` and be a valid snake_case identifier, otherwise the build fails with a clear message. Results are sorted.
   - `build.rs` emits `cargo:rerun-if-changed=src/slices` and writes `$OUT_DIR/slices.rs`: one `#[path = "<abs>/mod.rs"] pub mod <slice>;` per dir, `pub const FACTORIES: &[app::Factory]` (each slice's `pub const FACTORY`) and `pub const NAMES: &[&str]`.
   - `src/slices/mod.rs` documents the convention and `include!`s the generated file. A missing `FACTORY` is a compile error, which is the strongest form of "fails if a slice doesn't register". A test also checks that `NAMES` equals the dirs found on disk, and unit-tests the dir rule on a temp tree.
7. **Guard test** (`tests/`). Parse every `.rs` under each slice dir with syn. Collect `crate::<x>` roots from paths and use trees (including `use crate::{a, b}` groups) and from macro token streams. Allow only `events`, `eventstore`, `eventhandler`, `app` and `slices::<own slice>`. A `super::` chain that climbs above the slice root fails too (track depth through files and inline `mod`). Unit-test the checker on planted source strings: allowed cases, a foreign `crate::` module, another slice, `super::super` from the slice root, and a path inside a macro.
8. **Binary.**
   - `main` sets up the JSON tracing subscriber: stderr, INFO, `flatten_event(true)`, so the message and fields sit at top level.
   - It parses `Config`. `--help`/`--version` print and exit 0. Other parse errors log ERROR "invalid arguments" with an `error` field and exit 2.
   - It builds the slices from `underling::slices::FACTORIES` with `std::env::var(k).ok()`. A failure logs "invalid configuration" and exits 2.
   - It binds the address, turning a bare `:port` into `0.0.0.0:port`. A bind failure logs "listen" (`addr`, `error`) and exits 1.
   - It runs until SIGINT/SIGTERM. A run error logs "app stopped with error" and exits 1.
   - Integration test against `CARGO_BIN_EXE_underling`: `--help` exits 0, an unknown flag exits 2 with the log line, and SIGTERM (via `kill`) after "app started" exits 0 with "app shutting down" logged.

### Notes

- Store calls are synchronous redb calls, made directly from async code (HTTP handlers, the runner loop). Commits are short and the load is tiny. This matches Go and keeps the API plain. Revisit with `spawn_blocking` only if it ever shows up.
- Errors include their inner error's text in `Display`, because logs use `%err`, matching Go's wrapped messages.
- The log envelope differs from slog: `message` vs `msg`, `timestamp` vs `time`. Message strings and field names match, as the epic requires.
- Go's single-dash flags (`-addr`) are dropped: clap doesn't support them natively, and the epic makes them optional. Revisit at cutover if deploy scripts use them.
- The "invalid configuration" exit path can't be tested end to end until a slice with required config exists (011.02).
- `crate::events` doesn't exist yet. The guard allows it ahead of 011.02.

## Implementation Notes

- **Async `handle`, awaited inline.** `eventhandler::Handler` is an `#[async_trait]` trait with `fn name(&self) -> &str` and `async fn handle(&mut self, event: Event)`. Each handler runs in its own tokio task, so one handler's long `handle` (a child process, an HTTP call) never blocks another or the HTTP server. The runner never cancels `handle`. On stop it waits for the current event, checkpoints it, and goes no further, as in Go. For early exit, the handler `select!`s on the `CancellationToken` the app hands each automation. The app cancels that token before it stops the runner (step 2 before step 3), so for 011.03:
  - the investigator awaits `tokio::process` and `reqwest` futures inside `handle`;
  - it races them against the token and kills the child process group on cancel;
  - it records the shutdown outcome and returns.

  `&mut self` means a handler can hold state without a mutex. `async-trait` keeps `Box<dyn Handler>` simple. Native async-fn-in-trait isn't dyn-compatible and would need a hand-written erasure layer.
- **Public API (for 011.02/03):**
  - `eventstore`: `Store::open(dir)`, `Store::open_with_clock(dir, clock)`, `append(stream, expected, &[NewEvent]) -> Result<Appended { version, position }, Error>`, `read_after(position, limit)`, `checkpoint(name)`, `set_checkpoint(name, position)`, `subscribe() -> Subscription` (`wait().await`), `close()`.
    - `Event { stream_id, version, position, event_type, timestamp: DateTime<Utc>, payload: serde_json::Value }` and `NewEvent { event_type, payload }`.
    - A dedupe check is `matches!(err, eventstore::Error::Conflict { .. })`.
  - `eventhandler`: `Handler`, `Runner::start(Arc<Store>, Vec<Box<dyn Handler>>)` and `Runner::stop(self).await -> Result<(), Vec<Error>>` (every handler's error; a panic is `Error::Panicked(msg)`) and `Runner::panicked().await`. A handler panic shuts the app down; `run` returns it.
  - `app`:
    - Slice kinds: `StateChange::new(MethodFilter, &'static str path, |Arc<Store>| axum_handler)` (read back with `method()` and `path()`) and `Automation::new(|CancellationToken, Arc<Store>| handler)`.
    - Factories: `Factory::{StateChange, Automation}(fn(&Deps) -> Result<_, ConfigError>)`, `Deps { getenv: &dyn Fn(&str) -> Option<String> }` and `ConfigError = Box<dyn Error + Send + Sync>`.
    - Building and running: `build(&[Factory], &Deps)`, `Config` (clap), `run(&Config, TcpListener, Slices, CancellationToken) -> Result<(), app::Error>`.
  - `logging::json(writer)` is the shared subscriber. A slice is `src/slices/<name>/mod.rs` with `pub const FACTORY: app::Factory`.
- **Store calls are sync.** HTTP handlers and the runner call redb directly, without `spawn_blocking`. Commits are short and traffic is tiny, as in Go.
- **`Store::close` closes for real,** even while something still holds an `Arc<Store>`, so a restart can always reopen the file. Later calls return `Error::Closed`. Since the review fixes, a forced HTTP shutdown aborts the connection tasks and drops their handlers, so `shutdown_completes_when_a_request_outlives_the_timeout` no longer depends on it; it still covers anything a handler spawned that holds the store.
- **File name `underling.redb`,** not `underling.db`, so a leftover bbolt file in the data dir is never mistaken for the store.
- **Logs:**
  - The JSON envelope is tracing's, not slog's: `timestamp` and `message` instead of `time` and `msg`, with the fields flattened to top level and no `target`. Messages and field names match Go (`app started` with `addr` and `dataDir`, `app shutting down`, `stopping event handlers`, `event handler stopped` with `handler` and `error`, `invalid arguments`, `invalid configuration`, `listen`, `app stopped with error`).
  - Tasks are spawned with the current subscriber attached, so tests can capture logs per test (`src/testlog.rs`).
- **Deps has no logger.** Slices log through `tracing` macros, and the subscriber is global. Passing a dispatcher around would add nothing.
- **Factories are plain `fn` pointers,** so the generated `FACTORIES` can be a `const`. Build tests record call order in a `thread_local`, and "stops at the first error" uses a later factory that panics.
- **Wiring:**
  - `build.rs` and the tests share `build/slice_dirs.rs` via `#[path]`, so Go's "keep two copies identical" test isn't needed.
  - A slice dir without `mod.rs`, or with a name that isn't snake_case, fails the build. Go skipped such dirs, but a Rust dir without `mod.rs` is almost surely a mistake.
  - A slice without `FACTORY` fails to compile. I checked this by hand with a temporary probe slice, which also made the guard test fail on a planted `use crate::logging`.
- **Guard** (`tests/slice_imports.rs`):
  - It parses with syn and checks `crate::` roots in paths, use trees (including groups) and macro token streams, and catches `super::` chains that climb out of the slice (it tracks file depth and inline `mod`s).
  - It rejects any `#[path]` and `include!`; `include_str!`/`include_bytes!` may only read a relative path without `..`.
  - `crate::events` is allowed ahead of 011.02.
- **Flags:**
  - Durations go through `humantime` (`10s`, `30m`, `1h`, `1m30s` all work; Go's fractional `1.5h` doesn't).
  - A bare `:port` binds `0.0.0.0:port` (IPv4 only, unlike Go's dual-stack `:8080`).
  - Go's single-dash `-addr` isn't supported.
  - `--version` was added, since clap gives it for free.
- **Not covered here:** the "invalid configuration" exit path end to end. It needs a slice with required config (011.02). Two slices with the same method and path make axum panic at startup, as Go's mux does.
- **Deviations from the plan:** none of substance. The runner tests are unit tests in `src/eventhandler.rs`, and the app tests are in `src/app/tests.rs` (they need the crate-private log capture). `anyhow` isn't used.
- **TDD note:** the scenarios were ported from the Go tests together with the code. I checked a few mutations instead:
  - dropping the per-event stop check fails `stop_finishes_and_checkpoints_the_current_event_only`;
  - cancelling the automation token after `runner.stop()` fails the token test;
  - dropping `store.close()` failed the timeout test (no longer, see above).

### Review fixes

Fixed:

- **Header read timeout.** HTTP is served through hyper's HTTP/1 builder with a `TokioTimer` and a 10s header read timeout, like Go's `ReadHeaderTimeout` (`src/app/serve.rs`). The axum `Router` is still the service. `hyper_util`'s `GracefulShutdown` drains on shutdown; after the shutdown timeout the connection tasks are aborted, like Go's `srv.Close`. This uses `hyper::server::conn::http1` rather than `hyper_util`'s auto builder: the auto builder always compiles in HTTP/2 (`h2`), and the Go server didn't speak h2c either. Tested: a client that sends half its headers is disconnected; the timeout test checks the in-flight request is cut off.
- **Handler panics** are caught (`catch_unwind`). The handler logs "event handler stopped" with `error` = "event handler panicked: <msg>" at the time, stops without checkpointing the event, and `stop` returns `Error::Panicked(msg)`. (Round 2 widened the catch to the whole handler task and made the app shut down on it, see below.)
- **Yield after each event**, so a handler whose `handle` never really awaits can't pin a worker during catch-up. Tested on a current-thread runtime.
- **Guard bypasses:** the bare `crate` path (`use crate as root`, `crate::{self as root}`) and `extern crate self` are violations, a leading `self::` is stripped before the `super::` check (in macros too), and visibility restrictions (`pub(crate)`, `pub(in …)`) are ignored instead of read as paths.
- **`check_slice` depth** is tested on a fixture tree (`mod.rs`, `foo.rs`, `foo/bar.rs`, `foo/baz/mod.rs`) with legal and illegal `super::` chains.
- **`StateChange`'s `method` and `path`** are private with getters.
- **Drop cleanup:** `Runner` holds a drop guard on its stop token, `run` aborts the serve task when its future is dropped (`AbortOnDropHandle`) and cancels the automations' token. Tested for the runner and the server.
- **`Runner::stop` returns every handler error** (`Vec<Error>`), each already logged; `app::Error::StopHandlers` joins them.
- **Keyword slice dirs** (`type`, `mod`, …) fail the build with a clear message.
- **Nits:** one `From` impl per redb error type instead of the blanket impl, `rust-version = "1.90"` (redb's minimum; edition 2024 and let chains alone need 1.88), and `Store::close` documents that redb can't report close failures.

Rejected:

- **Unreachable `Error::Serve`:** it still covers `local_addr` failing and the serve task panicking, so it stays.
- **Vacuous wiring test:** it's meant to be vacuous until slices exist, as the criteria say; a missing `FACTORY` is a compile error anyway.
- **clap output on stderr:** clap prints its usage text to stderr before the JSON line. It helps humans at the terminal, and the JSON line is still there for log parsers.
- **Second SIGINT forcing exit:** Go's `signal.NotifyContext` swallows later signals too; the shutdown timeout bounds the drain.
- **Unix-only build:** the deploy target is Linux (and dev is macOS); Windows isn't a target.
- **chrono fractional-seconds format:** chrono writes 0, 3, 6 or 9 fractional digits where Go's `RFC3339Nano` trims trailing zeros. Both are valid RFC 3339 and parse to the same instant, and the store is fresh, so nothing compares the strings.

Round 2, fixed:

- **A handler panic shuts the app down,** as Go's crash did. `Runner::panicked()` completes on a caught panic (now caught around the whole handler task, so panics outside `handle` count too). `run` selects on it next to the shutdown token, shuts down in order and returns the panic as `StopHandlers`, so `main` exits 1 and a supervisor restarts underling, resuming from the checkpoint. A store error still only stops its handler and the app keeps running. Tested in the runner (panic signals, store error doesn't) and in the app.
- **No waiting on aborted connections.** On a drain timeout `serve` calls `abort_all()` and returns, like Go's `srv.Close`. Tested: a request stuck in `std::thread::sleep(2s)` doesn't hold `run` past 1s, on a multi-thread runtime.
- **Guard:** a group after `pub` in macro tokens is skipped only if it's a real restriction (`crate`, `self`, `super`, `in …`), so `struct S(pub (crate::other::T, u8))` is caught. `#[path]` and `include!` are always violations. `include_str!`/`include_bytes!` are allowed for relative paths without `..`, since they only embed data, such as a prompt file next to the slice.
- **Automation token on drop:** tested that aborting `run` cancels the token an automation is awaiting.
- **Serve ending early** ends `run` like Go's `Serve` returning: it shuts down in order and returns `Error::Serve`. Untested: `serve` retries accept errors, so only a panic in the server ends it early, and there's no way to cause one without a test hook.
- **`TCP_NODELAY`** is set on accepted connections, as Go does (untested; the server side's socket isn't reachable from a test).

Round 2, rejected (info):

- **No HTTP upgrades** (`with_upgrades`): no slice needs WebSockets or similar.
- **hyper's 100-header limit vs Go's 1 MB header limit:** the callers (Sentry webhooks, a browser for the OAuth callback) send far fewer headers.
- **Accept errors are retried, not returned:** this matches Go's behaviour for temporary errors, and a listener that fails for good would only spin with a 100ms back-off and a warning.
- **The `HEADER_READ_TIMEOUT` wiring constant is untested:** the mechanism is tested with a short timeout, and a test pinning the constant would only repeat it.

Round 3, fixed:

- **Guard:** `#[cfg_attr(…, path = "…")]` counts as `#[path]`. A `use` whose last segment is `include`, `include_str` or `include_bytes` (`use std::include as inc;`, `use core::{include_str as s}`) is a violation, so an alias can't dodge the include checks. Passing `include` through a `macro_rules!` metavariable still slips through. That's accepted: it takes deliberate evasion, not an accident.
- **Prompt exit:** `main` builds the runtime by hand and ends with `shutdown_timeout(Duration::ZERO)`, so a worker stuck in sync code (a request cut off at the shutdown timeout) doesn't keep the process alive after `run` returns, as with Go's exit. The cli tests stay green. No end-to-end test: it needs a slice with a request that blocks.

Round 3, rejected:

- **A `reason` field on "app shutting down":** Go's log line has none, and the cause is logged on its own ("event handler stopped").
- **The `include_str!`/`include_bytes!` allowance:** relative paths without `..` stay inside the slice's directory, and embedding data couples nothing.
