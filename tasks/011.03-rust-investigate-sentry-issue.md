## Rust: Investigate Sentry Issue Slice

Part of epic 011. Port `internal/slices/investigatesentryissue` to Rust with the task 010 shape: a readable flow behind small traits, plus sub-modules for the git workspace, the sandboxed claude child and the GitHub client. Behaviour, config, events, logs and every isolation and safety property must match `docs/event-model.md` § "Automation: investigate Sentry issue". Port the given/when/then tests and the infrastructure tests, including the re-exec'd fake `claude`, the local bare remote and the in-memory GitHub.

### Acceptance Criteria

The Go package (all files, sub-packages and tests) is the spec; "as Go" means byte-for-byte for persisted payloads, failure reasons, log messages and field names, argv, env and settings JSON.

- **Slice.** `src/slices/investigate_sentry_issue/`, wired by `build.rs`, an automation whose handler and checkpoint name is `sentry-issue-investigator`. Layout as task 010: a flow module holding only decisions, behind small traits for the cloner, the run and the PR opener; sub-modules `workspace`, `claude` and `github` that never use the flow (`flow.rs`, `outcome.rs`, `infrastructure.rs` or `mod.rs`). A sub-module may use a sibling sub-module (as Go's `claude` uses `workspace`) and the leaf helper modules at the slice root that use nothing else in the slice (`paths.rs`, `process.rs`). The import guard stays green.
- **Config**, read through `Deps::getenv` when the factory runs; every invalid value is an error naming its variable, so the binary logs "invalid configuration" and exits 2. All errors are reported together (Go's `errors.Join`, newline-separated).
  - Required: `SENTRY_GITHUB_REPOS` (`<projectId>=<owner>/<repo>`, comma-separated, entries trimmed; integer ids, each mapped once; owner and repo match `[A-Za-z0-9_.-]+` and aren't `.` or `..`), `GITHUB_TOKEN`, `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `CLAUDE_PLUGIN_DIRS` (comma-separated, trimmed, no empty entry, each absolute: review fix, Go took relative ones).
  - Optional: `INVESTIGATION_TIMEOUT` (`30m`) and `INVESTIGATION_MAX_AGE` (`1h`), positive Go durations (parsed as Go's `time.ParseDuration` does); `CLAUDE_BIN` (`claude`); `INVESTIGATION_WORK_DIR` (absolute, review fix; default `<temp dir>/heinzel-investigations-<uid>`); `INVESTIGATION_DENY_READ` (comma-separated absolute paths, cleaned); `HOME` (cleaned; heinzel's own HOME, denied to the child) and `PATH` (handed to the child and to git).
  - Startup checks as Go's `New`: an existing work dir must pass the work-dir check (`INVESTIGATION_WORK_DIR: <reason>`); `resolveReadPaths` rejects a work dir under HOME or a deny path, a plugin dir overlapping HOME, a deny path or the work dir (either direction), and a claude binary dir holding a denied path, with Go's messages; it sets the readable paths (plugin dirs, then the claude binary's dir if found on PATH, symlinks resolved). One WARN per PATH entry under a denied path that no readable path re-opens: "PATH entry lies under a path the child may not read; tools there won't run inside the sandbox" with `handler`, `dir`, `denied`.
  - Production values: GitHub API `https://api.github.com`, clone base `https://github.com/` (`<base><owner>/<repo>.git`), 30s GitHub request timeout, the real clock read once when the handler is built. Tests inject all four.
- **Flow** (`Handle`), as Go's `investigator.go`:
  - other event types are ignored silently; an undecodable alert logs ERROR "decode sentry issue alert" (`handler`, `position`, `error`) and records nothing;
  - stale (stored before handler start − max age) → Skipped `stale` at v0, checked before unmapped → Skipped `unmapped` at v0;
  - if the automation token is cancelled: INFO "heinzel is shutting down; sentry issue alert left unhandled", nothing recorded;
  - Started `{issueId, project, repo, branch}` at v0, INFO "sentry issue investigation started" (`repo`, `branch`); a conflict at v0 logs INFO "sentry issue already handled" (`outcome`=`duplicate`) and stops;
  - then clone → `clone`; claude timeout → `timeout`, other claude error → `claude`; stray branches or their listing error → `claude` ("claude committed on branches other than <branch>, which heinzel doesn't push: <a, b>" / "collect claude's commits: <err>"); count error → `claude` ("collect claude's commits: <err>"); right after Claude and before any fetch, a mirror that differs from heinzel's manifest → `push` ("the mirror changed while claude ran (<path>), so heinzel won't push from it", review fix); 0 commits → NoChanges; changed-paths error → `push`; CI config (Go's dirs and root files, plus the bare dir names, `.gitlab/`, `.woodpecker/`, `.azure-pipelines/`, `.drone.yml`, `.woodpecker.yml`, `appveyor.yml` and `.appveyor.yml`: review fix) → `push` "changes CI configuration, so heinzel won't push it: <first 5>, and N more"; push error → `push`, including the push-time refusals ("the mirror's git config changed", "the mirror holds <commondir|.git|gitdir|objects/info/alternates|refs/replace|shallow>", "the mirror holds a symlink at <path>", each ", so heinzel won't push from it"); PR error → `pr`; else PullRequestOpened `{issueId, prUrl}`. The outcome goes at v1. Once the token is cancelled, any failure is stage `shutdown`. The workspace is always removed; a removal failure logs ERROR "remove investigation workspace" (`handler`, `issueId`, `dir`, `error`).
  - Each recorded outcome logs "sentry issue investigation finished" with `handler`, `position`, `issueId`, `outcome` (`pr_opened`/`no_changes`/`skipped`/`failed`) and `prUrl`, `reason`, or `stage`+`reason`; failed at WARN, the rest INFO. Other store errors log ERROR "record sentry issue investigation" (`type`, `error`).
  - Stream `sentry-issue-investigation-<key>`, branch `heinzel/sentry-<key>`, key = the issue id if `[A-Za-z0-9_-]+`, else its hex sha256.
- **Prompt** as Go: `/at:auto-task ` + the instruction block with the branch + the issue details as 2-space-indented JSON (Go's key order and omissions, title capped at 2000 chars) + `\n`.
- **PR** as Go: title `Fix Sentry issue <id>: <title>`, mentions neutralised (U+200B after every `@`), capped at 200 chars. Body: header (`Sentry issue [<id>](<webUrl>): <title>\n\n## Claude's summary\n\n`; review fix: the link only for an `https://` URL without whitespace, control characters or `()<>`, else the plain id; `&#64;`, `&#x40;` and `&commat;` in any case and with any leading zeros are broken up too) + trimmed, neutralised summary + footer, at most 60000 bytes; only the summary is cut, at a char boundary, closing a ``` or ~~~ fence the cut leaves open with its own run (CommonMark rules as Go's `openFence`); the header is cut only if it alone would crowd out the footer.
- **Workspace** as Go: work dir created 0700 and checked (Unix: real dir, not a symlink, owned by us, `mode & 0o077 == 0`, Go's messages, mode printed like `0755`, never chmodded) at each run, failing stage `clone`; run dir `heinzel-investigation-*` with symlinks resolved; `mirror.git` (bare clone, with the token), `repo` (clone of the mirror with `--no-hardlinks`, local identity `heinzel <heinzel@users.noreply.github.com>`, `commit.gpgsign=false`, on the new branch), `home`, `claude-config`, `git-home` (0700); siblings listed sorted; default branch and base from the mirror's HEAD; stray branches via `refs/heinzel/clone/*` with Go's `rev-list --count <ref> --not --branches [refs/heinzel/clone/<branch>]`, a renamed or deleted branch handled as Go; `diff --name-only --no-renames -z`; push from the mirror with `push --quiet --no-verify <repo URL> <ref>:<ref>` (review fixes, beyond Go: every git command on the mirror pins `GIT_DIR` and `GIT_COMMON_DIR`, sets `GIT_NO_REPLACE_OBJECTS=1`, `core.hooksPath=/dev/null` and only allows the file and https protocols; the mirror's dirs are 0500 while Claude runs; a manifest of the mirror must be unchanged after Claude; at push the config must be the same regular file and no foreign path or symlink may exist); removal makes every dir 0700 without following symlinks, then deletes. On a failed setup it removes what it created.
- **git runner** as Go: env exactly `PATH`, `HOME=<git-home>`, `GIT_TERMINAL_PROMPT=0`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null`; for clone and push only, `GIT_CONFIG_COUNT=3` with `http.extraHeader: Authorization: Basic base64(x-access-token:<token>)`, `http.lowSpeedLimit=1000`, `http.lowSpeedTime=60`. The token is never in argv, a URL or a config file. Timeouts 10 min for clone/fetch/push (subcommand found past `-c`/`-C` options), 1 min otherwise; a killed command's output is read for at most 10s more. Errors: `git <subcommand>: <cause>: <combined output, trimmed, last 2048 bytes, token → [redacted]>`, where the cause reads like Go's (`exit status N`, `context deadline exceeded (signal: killed)`, `context canceled (signal: killed)`).
- **claude child** as Go: argv `--bare -p --verbose --output-format stream-json --no-session-persistence --setting-sources "" --settings <json> --permission-mode acceptEdits --permission-prompts none --plugin-dir <each>`, cwd the clone, prompt on stdin, env exactly `PATH`, `HOME`, `CLAUDE_CONFIG_DIR`, `ANTHROPIC_API_KEY`, `OPENAI_API_KEY` (in that order). The settings JSON has Go's key order and values (permissions with `Read(//proc/**)` then `Read(/<p>/**)` rules, each followed by an `Edit(/<p>/**)` rule (review fix), for HOME and deny paths with their resolved forms, siblings, mirror and git-home; the sandbox block with `allowWrite`, `denyRead`, `allowRead`, `allowedDomains: ["api.openai.com"]`).
  - Run: own process group (`process_group(0)`); killed as a group (SIGKILL via `nix::sys::signal::killpg`) after `INVESTIGATION_TIMEOUT` or on the automation token, and the group is killed again after every exit; then the output is drained for at most 5s. Results, in Go's order: shutdown → "heinzel shut down while claude was running"; timeout → "claude did not finish within <Go duration, e.g. 30m0s>", recognisable by the flow as a timeout; non-zero exit → `claude: exit status N[: summary][: stderr tail 2048 bytes]`; read error; init check failure → "claude's session did not start as configured: …" (no init event, permission mode not `acceptEdits`, no plugin loaded from a dir, plugin errors with their raw JSON); last event not a successful `result` → "claude did not end with a successful result[: …]"; else the result text is the summary. Spawn failure → `start claude: …`.
  - stream-json reading as Go: lines of any length, trimmed, non-objects and objects without `type` skipped, the first `system/init` kept, the last event decides.
- **GitHub** as Go: `POST <api>/repos/<owner>/<repo>/pulls` (trailing `/` on the base trimmed) with `Authorization: Bearer`, `Accept: application/vnd.github+json`, `X-GitHub-Api-Version: 2022-11-28`, `Content-Type: application/json`, body `{title, head, base, body, draft: true}`; the response read up to 1 MiB; non-201 → `create pull request: status N: <trimmed body, first 512 bytes>`; no `html_url` → `create pull request: no html_url in response`. reqwest with rustls.
- **Tests.**
  - Given/when/then flow tests in memory (real store in a temp dir, fakes for cloner, run and PR opener, no processes, git or network), one per Go `investigator_test.go` scenario, with `then` checking every event the alert added to any stream.
  - Infrastructure tests next to each sub-module, porting the Go tests of `workspace`, `claude` (command, settings, stream, init, run, timeout, shutdown kill, grandchild), `github`, config, PR, prompt, CI paths and names, plus the two follow-ups task 010 left open: push runs with hooks off (a pre-push hook planted in the mirror doesn't run), and cancelling a hung run kills its process group.
  - End-to-end tests with real git, a local bare remote, a fake `claude` and a local GitHub: happy path to a draft PR (no token form on disk or in the remote's config, nothing left in the work dir), child env holding no heinzel secrets, restart dedupe, the two clock-based stale tests, the PATH warning, invalid config, and the two work-dir tests.
  - Existing app-level tests (`tests/sentry_alert.rs`, `tests/cli.rs`) get the new required env and stay green.
- **Unix only.** Process groups and the work-dir checks use Unix APIs; the crate is already Unix-only (`main` uses Unix signals). The slice states this explicitly; Windows isn't a target.
- `#![forbid(unsafe_code)]` stays. The Go code stays untouched and keeps passing.

## Implementation Plan

### TLDR

Port the Go package module by module: pure text helpers and config first, then the three infrastructure sub-modules with their tests, then the flow with in-memory given/when/then tests, then the real wiring and a handful of end-to-end tests. Fake `claude`s are shell scripts the tests write; the fake GitHub is a local axum server.

### Steps

1. **Crates.** `cargo add`: `reqwest` (no default features; `rustls`, `json`), `nix` (`signal`, `user`), `base64`; move `tempfile` to `[dependencies]` (run dirs, as Go's `MkdirTemp`); enable `serde_json`'s `raw_value` (plugin errors keep their raw JSON); add tokio's `process` and `io-util` features to the normal dependency. Check the dependency tree has no `openssl`.
2. **Text and names** (slice root): issue key, stream and branch names, char/byte truncation, mention neutralising, CI paths with `first_n`, the prompt, and the PR title/body with the fence logic. Port `stream_test`, `ciconfig_test`, `prompt_test` and `pr_test` as they are, including the `openFence` table.
3. **Config** (slice root): parse into a config struct; the path helpers (`with_resolved`, `resolve_path`, `within`, `first_containing`, `look_path`) live in `claude`, as in Go, with a lexical `clean` matching Go's `filepath.Clean` (trailing slash, `.`/`..`); `resolve_path` uses `canonicalize`, falling back to `clean`. Port `config_test` (every invalid value names its variable) and the `resolveReadPaths` tables.
4. **`workspace`.** Async git runner on `tokio::process` with `env_clear`; combine stdout and stderr into one pipe (`std::io::pipe`, cloned writer) so the output keeps Go's interleaving; on timeout or token cancel kill git (not a group, as Go), then read the output for at most the wait delay. Keep timeouts and the wait delay as runner fields so tests can shorten them. Port every `workspace_test`, `workdir_unix_test` and `gitwait_unix_test` scenario (the latter with Go's fake-`git` script and a 1s timeout). Add: a pre-push hook planted in the mirror that writes a marker file doesn't run on `push`.
5. **`claude`.** Command and settings as plain data (serde structs in Go's field order), then `run(cmd, timeout, token)`: spawn in its own group, write stdin, read stdout and stderr concurrently with the wait (the readers must keep running while waiting or a full pipe blocks the child); keep partial stream output if the 5s drain runs out. Format exit statuses and durations like Go (`exit status 1`, `signal: killed`; `30m0s`, `500ms`, `1h0m0s`, `1m30s`). The timeout error is a type the flow can recognise without the claude module (a trait or an `is_timeout` method on the run's error, never string matching). Port `claude_test`, `stream_test`, `run_test`, `grandchild_unix_test`; add a hung-run cancel test that checks a grandchild in the group is gone.
6. **`github`.** A small reqwest client (base URL injected, 30s timeout in production). Tests run against an axum server on `127.0.0.1:0` that records method, path, headers and body: draft body and headers, non-201 with the 512-byte excerpt, missing `html_url`.
7. **Flow.** The investigator struct implementing `eventhandler::Handler`, holding the token, store, `stale_before`, repos and `Box<dyn …>` cloner and PR opener; `async_trait` traits for cloner, run and PR opener, with error types that are plain `String` reasons plus the timeout flag. Port every `investigator_test` scenario as given/when/then, with a `then` that compares all events after the given ones (stream, type, payload) and log assertions via a local tracing capture, as the record slice does. Port `infrastructure_test` (a real claude timeout counts as timed out; another error doesn't).
8. **Wiring** (`mod.rs`): `FACTORY` reads the config with the production values and builds the automation; a private `new(Params)` takes getenv, the GitHub and clone URLs, the HTTP timeout and a clock, so tests inject them. The handler reads the clock once when the app builds it. Put `#[cfg(not(unix))] compile_error!(…)` in the slice to state it's Unix-only.
9. **End-to-end tests** in the slice (they need the private `new`): a script fake `claude` that reads its mode from `<work dir>/fake-claude-mode` (two levels above its cwd), records argv (NUL-separated), env, cwd (`pwd -P`), stdin and the files under its run dir holding any token form (`grep -rlF`), emits an init event matching its `--plugin-dir` args, and in `happy` mode commits `fix.txt` ("Fix blooopy"). The test, not the script, checks the recorded settings (sandbox on, unsandboxed off, `allowWrite == [clone, HOME]`, `denyRead ∋ work dir`, `allowRead` starting with clone, HOME, config dir). Port the Go `e2e_test.go` and `workdir_unix_ext_test.go` scenarios.
10. **App-level tests.** Give `tests/sentry_alert.rs` and `tests/cli.rs` the investigator's required env (a mapping for another project, a private 0700 temp work dir, plugin dirs outside HOME), so the alert they post is skipped as unmapped.

### Notes

- **Fake `claude` as scripts, not a bin.** `CARGO_BIN_EXE_*` isn't set for lib unit tests (checked with cargo 1.99), so a test-only `[[bin]]` would push the run and e2e tests into `tests/`, and would need a public `new(Params)` and a binary that ships with `cargo build`. Scripts keep each test next to its code with private access, and the crate is Unix-only anyway. The cost: `/bin/sh` adds `PWD`, `SHLVL` and `_` to the env it records, so the e2e env test drops exactly those three before comparing with the five allowed keys. The unit test on the built command checks the exact env, and `env_clear` guarantees nothing else is inherited.
- Linux can fail a freshly written script with `ETXTBSY` when another test forks at the same moment. Dev is macOS; if it flakes in the cutover's Linux build, retry the spawn in the test helper.
- The git runner and claude run take the automation token, which replaces Go's ctx; a git command killed by it reads `context canceled (signal: killed)`, as Go's.
- Prompt JSON: Go's `MarshalIndent` HTML-escapes `<`, `>` and `&`; serde_json doesn't. The prompt isn't persisted, so accept the difference.
- The settings JSON is compact `serde_json::to_string` of structs in Go's field order. That is byte-identical to Go's for paths without `<`, `>`, `&`, U+2028 or U+2029, which Go escapes.
- Store calls stay synchronous, as in the other slices.

## Implementation Notes

- **Layout** (`src/slices/investigate_sentry_issue/`):
  - `flow.rs` is the decision path: `Investigator` (the `eventhandler::Handler`) plus the `Cloner`, `Run` and `PrOpener` traits, a `ClaudeFailure { reason, timed_out }` and its own `PullRequest`. It uses none of the sub-modules. Failures travel as a private `Failure { stage, reason }` through `?`, and `investigate` turns them into the outcome, switching to stage `shutdown` once the token is cancelled.
  - `outcome.rs` holds the `Outcome` enum and a `Recorder` (store, stream, position, issue id) that appends and writes the log lines.
  - The rest of the slice root: `config.rs`, `names.rs`, `text.rs`, `ci_config.rs`, `prompt.rs` and `pr.rs`. `infrastructure.rs` implements the traits with the sub-modules. `mod.rs` holds `FACTORY`, `Params`, `new` and `handler_builder`.
  - Sub-modules: `workspace` (`mod.rs`, `git.rs`, `manifest.rs`, `work_dir.rs`), `claude` (`mod.rs` for the command and settings, `run.rs`, `stream.rs`) and `github`. They use only each other (`claude` uses `workspace::Workspace`, as in Go) and the leaf helpers at the slice root: `paths.rs` (lexical paths, symlink resolution, `look_path`) and `process.rs` (exit statuses worded as Go words them). `duration.rs` (Go's `ParseDuration`) and `test_logs.rs` (the tests' log capture) are slice-root helpers too.
- **Fake claude: shell scripts.** `CARGO_BIN_EXE_*` isn't set for lib unit tests, so a test-only bin would have pushed every run and e2e test into `tests/` and needed a public constructor. Each test writes its own `#!/bin/sh` fake instead. The e2e fake records argv (NUL-separated), env, `pwd -P`, stdin and `grep -rlF` hits for the three token forms into `<work dir>/fake-claude-calls/<n>/`. The test, not the script, checks the settings. The env test drops `PWD`, `SHLVL` and `_`, which `/bin/sh` adds itself; the claude unit test checks the exact env on the built command.
- **`handler_builder`.** `Automation::into_handler` is private to `app`, so `new` is split: `handler_builder(Params)` loads and checks the config and returns a reusable `Fn(CancellationToken, Arc<Store>) -> Investigator`, and `new` wraps it in `Automation::new`. The e2e tests call the builder directly, twice for the restart test.
- **Go-compatible text** where it gets persisted or logged:
  - `go_duration` formats durations like Go (`30m0s`, `500ms`, `1h0m0s`);
  - `process::exit_reason` gives `exit status N` and `signal: killed`;
  - git's stop causes read `context deadline exceeded (signal: killed)` and `context canceled (signal: killed)`;
  - modes print as `0755`.
- **git output.** stdout and stderr share one `std::io::pipe`, turned into a `tokio::net::unix::pipe::Receiver`, so the combined output keeps git's order. After the command exits or is killed, the output is read for at most the wait delay. The runner holds the timeouts and the wait delay as fields, so tests can shorten them.
- **claude run.** The pipes are read concurrently with `child.wait()`. On a timeout or cancel the group is killed (`nix::sys::signal::killpg`), and it is killed again after every exit. Reading then gets 5s; if that runs out, the partial stream output read so far is kept. `tokio`'s `Child::wait` doesn't wait for the pipes, so a grandchild holding stdout can't delay the run.
- **Added tests:**
  - push runs with hooks off (a pre-push hook planted in the mirror doesn't run);
  - shutdown kills a grandchild in claude's process group;
  - cancelling a git command reads `context canceled (signal: killed)`;
  - a store failure logs "record sentry issue investigation" with `type`;
  - the exact settings JSON string, the GitHub request bytes, and an unreachable GitHub.
- **App-level tests.** `tests/cli.rs` and `tests/sentry_alert.rs` now set the investigator's required env, with project 2 mapped and a work dir that doesn't exist. Factories run in slice-name order, so the investigator's config is checked before `SENTRY_CLIENT_SECRET`. `sentry_alert.rs`'s `stop()` now returns only `SentryIssueAlertReceived` events, since the investigator also records a `Skipped unmapped`, and when it lands is racy. Asserting that skip end to end is left to 011.04's e2e port.
- **Unix only.** The slice has `#[cfg(not(unix))] compile_error!`, and uses Unix APIs without stubs. `main` was already Unix-only.
- **Crates:** `reqwest` (`rustls`, `json`; its default crypto provider is aws-lc-rs, whose `aws-lc-sys` needs a C toolchain; it built here, and the cutover's cross build must handle it), `nix` (`signal`, `user`), `base64`, and `tempfile` moved to the normal dependencies. `serde_json` gained `raw_value`, tokio gained `process` and `io-util`. The dev-dependency copies of `reqwest`, `tokio` and `tempfile` were dropped as redundant. No openssl.
- **Mutation checks.** Each of these was caught by at least one test:
  - git: dropping `GIT_CONFIG_GLOBAL`; pushing with hooks on; git's `HOME` set to the child's; the token written to the clone's config;
  - flow: no shutdown override; no cancel check before Started; unmapped checked before stale; timeouts not recognised;
  - claude: the child inheriting heinzel's env; `allowUnsandboxedCommands: true`; no `process_group(0)`; no group kill after exit;
  - workspace: not excluding the investigation branch in the stray check; no work-dir check at run start; a gone branch counted;
  - text: CI dirs ignored; the PR title not neutralised; a cut fence left open.
- **Accepted deviations from Go:**
  - OS and library error text in reasons is Rust's, e.g. `No such file or directory (os error 2)`, `start claude: …`, and reqwest's transport errors. Go's matching prefixes are kept.
  - A PR request cut off by shutdown reads `create pull request: heinzel shut down`. Go wrapped the context error. The stage is `shutdown` either way.
  - The prompt's issue JSON isn't HTML-escaped. Go's `MarshalIndent` writes `<` as `<`.
  - Config errors come in a fixed order. Go's iterated a map for the three required keys.
  - Signals Go names but the `process` table doesn't read `signal: signal N`. The table covers HUP, INT, KILL, SEGV, PIPE and TERM.
  - Run dir suffixes come from `tempfile` (alphanumeric), not Go's digits.
  - JSON decoding of stream lines and the stored alert follows serde (exact-case keys). The stream decoder still rejects arrays and non-objects, as Go does.
- **Follow-ups:**
  - Linux may hit `ETXTBSY` on a freshly written fake script if another test forks at the same moment. Dev is macOS; retry the spawn in the test helper if the cutover's Linux build flakes.
  - The manual smoke run with the real `claude` from task 009 is still open.

### Review fixes

Three reviews (code, Go parity, security). Fixed, one or a few commits each:

- **S1, the mirror** (an intended improvement over Go, which has the same gap). Only Claude Code's own check of where edits may go kept the unsandboxed Edit tool out of `mirror.git`: through a symlink in the clone, it could have written the mirror's config (a push URL that sends the token elsewhere) or a hook (which a fetch runs outside the sandbox). Now:
  - every `Read(...)` deny rule has an `Edit(...)` twin;
  - every git command in the mirror runs with `-c core.hooksPath=/dev/null`: the fetches, `for-each-ref`, `rev-list`, `diff`, `symbolic-ref`, `rev-parse` and push;
  - the push names the repo's URL (`<clone base><owner>/<repo>.git`), not `origin`;
  - heinzel keeps the mirror's config file bytes after setup. The flow checks them right after Claude, before fetching anything back, and the push checks them again. A mismatch fails stage `push` with "the mirror's git config changed while claude ran, so heinzel won't push from it". I compare the raw file rather than `git config --local --list`: it's stricter and needs no git. I didn't add the alternative chmod: the Edit tool's atomic rename would replace a 0400 file in a writable dir anyway.

  Tests:
  - workspace: no mirror hook runs while inspecting and pushing; the push goes to the URL, not the remote; a changed config stops the push;
  - flow: a changed mirror is neither fetched into nor pushed;
  - e2e with hostile fakes that write the mirror directly: `hostile-hooks` still opens the PR and no hook runs; `hostile-config` fails stage `push`, and nothing reaches the remote, the attacker repo or GitHub.
- **S8.** The Read/Edit rules for siblings, the mirror and `git-home`, and the `denyRead` entry for the work dir, come in the work dir's configured form too, when it differs from the resolved one (`Workspace::given_work_dir`).
- **S2.** CI paths also match the bare names `.github`, `.circleci` and `.buildkite` (a file, symlink or submodule there). Also new: `.gitlab/`, `.woodpecker/`, `.drone.yml`, `.woodpecker.yml` and `appveyor.yml`. I added `.appveyor.yml` and `.azure-pipelines/` as well, both real CI config locations. **011.04:** update the docs table.
- **S3.** The Sentry link goes into the PR body only if it starts with `https://` and holds no whitespace, control characters or `()<>`; otherwise the header names the issue id in plain text. `&#64;`, `&#x40;` (leading zeros allowed) and `&commat;`, in any case, are broken up with a U+200B after the `&`.
- **S4.** Git errors redact the token as the header's base64, as bare base64 and raw (so `x-access-token:<token>` too). `Debug` is hand-written and redacts on the slice `Config`, `claude::Config`, `Cmd` (env values), `GitRunner` and `github::Client`. `Workspace` keeps its derived `Debug`, which goes through `GitRunner`'s.
- **C1, P3, P5.** Workspace removal runs in `spawn_blocking`, and a join error is logged like an I/O error. `Run::remove` is async. A `WorkspaceRun` dropped unremoved, as when the flow panics, removes its dir in a background task. `claude::run` kills its process group from a drop guard, so a panic or a dropped future kills it too. A run dir that is already gone counts as removed.
- **C2.** claude's stderr goes through a bounded 2048-byte tail buffer.
- **C3.** The path helpers moved to the slice root (`paths.rs`).
- **C4.** Tests assert "sentry issue investigation started" (`repo`, `branch`), the finished lines for `pr_opened` (`prUrl`) and `no_changes`, and ERROR "remove investigation workspace" (`handler`, `issueId`, `dir`, `error`), set off by making the work dir read-only. `test_logs.rs` now uses `crate::logging::json`'s settings (no target, no spans, INFO).
- **C5.** The flow builds failures with `Failure::new(stage, reason)` and picks the claude stage with a plain `if`.
- **P1.** The slice parses durations with a port of Go's `time.ParseDuration`. That covers the units `ns`, `us`, `µs`, `μs`, `ms`, `s`, `m` and `h`, decimals, a sign, combined units and `0` alone; overflow is rejected. The fraction is computed in `f64`, as Go does: integer maths gives `0.3333333333333333333h` as 19m59.999…s, where Go gives 20m. Errors are Go's ("time: invalid duration …", "missing unit", "unknown unit"). The tests cover Go's `TestParseDuration` cases. The app's CLI flags still use humantime, as 011.01 decided.
- **P2.** A relative `INVESTIGATION_WORK_DIR` or `CLAUDE_PLUGIN_DIRS` entry is rejected: `"…" is not an absolute path`.
- **P6.** Once the token is cancelled, git isn't started; its error reads `git <sub>: context canceled (context canceled): `, as Go's exec words it. claude isn't started either; that gives `RunError::Shutdown`, where Go said `start claude: context canceled`. The stage is `shutdown` either way.

Mutation checks of the fixes, each killed by at least one test:
- mirror git without hooks off;
- a push to `origin`;
- the push's config check removed, the flow's check removed, or both;
- no Edit rules; no configured forms;
- the header form not redacted;
- a dropped run not removed; no group kill on drop;
- unbounded stderr;
- git started after shutdown; a missing dir being an error;
- bare CI dir names not matched; any link allowed; entities left alone;
- relative work or plugin dirs allowed;
- the removal not logged; the started line without `repo`;
- integer fraction maths in the duration parser.

More accepted deviations from Go:
- The init event decodes strictly: a type error anywhere drops all of it, where Go keeps the fields decoded before the error.
- If git exits but something still holds its output pipe, the command succeeds with the output read so far after the wait delay. Go fails it.
- A run counts as timed out only when the deadline killed the child. Go also counted a child that exited just as the deadline passed.
- Small text differences: Rust's `{:?}` quoting instead of Go's `%q` for non-ASCII; U+FFFD for invalid UTF-8 in output tails, where Go keeps the raw bytes; `trim_ascii` on stream lines instead of Unicode trimming; trailing slashes trimmed from the GitHub base URL, as Go's `TrimSuffix` does but repeatedly.

Rejected review items, for 011.04's docs:
- **A `setsid` daemon escapes claude's process group** and outlives the run. Go has the same gap. Containing it needs a container or a dedicated uid; document it with the isolation model.
- **Work-dir TOCTOU.** Between the check and use, another user could swap the work dir, but only if its parent is writable to them and not sticky. The default parent, the OS temp dir, is sticky. Document that a configured work dir's parent must be private or sticky.
- **The `make_removable` chmod race** is a denial of service at worst, and needs an escaped daemon (see above).

### Review fixes, round 2

A security review of round 1 got past the config-bytes check on git 2.50.1, through the real `Workspace` API, without changing the config:
- a `commondir` in the mirror pointing at a bare repo built in the clone, whose `url.<attacker>.insteadOf` redirected the push (and the token), and whose `protocol.ext.allow=always` with an `ext::` `insteadOf` for the clone ran code outside the sandbox during the first fetch;
- a `.git` gitfile in the mirror doing the same;
- a replace ref hiding a CI commit from `changed_paths`.

Fixed:

1. **git pinned to the mirror.** Every git command on the mirror runs with `GIT_DIR` and `GIT_COMMON_DIR` set to it, `GIT_NO_REPLACE_OBJECTS=1`, and `-c core.hooksPath=/dev/null`. It also gets `-c protocol.allow=never`, `protocol.file.allow=always` and `protocol.https.allow=always`, plus explicit `never` for `http`, `ext`, `fd`, `ssh` and `git`: a specific `protocol.<name>.allow` in a config file beats the general key, while `-c` beats a config file for the same key. Both clones get the protocol limits too. Local paths (the tests' remotes, the clone) are the `file` protocol.
2. **A manifest of the whole mirror** (`workspace/manifest.rs`). It records each entry by lstat: its relative path and type, mode for dirs and files, the target for symlinks, a sha256 for files up to 1 MiB, and size, mtime and inode for bigger ones (packs). It is taken at the end of setup and must match exactly right after Claude. That check is the flow's existing step, before any fetch, now with the first differing path in the reason. At push, `check_push` requires the config to be a regular file with the same bytes, `commondir`, `.git`, `gitdir`, `objects/info/alternates`, `refs/replace` and `shallow` to be absent, and no symlink anywhere in the mirror.
3. **The mirror is locked while Claude runs.** `WorkspaceRun::claude` sets every dir in the mirror to 0500 before the run and gives each its recorded mode back afterwards, before heinzel's own fetches. If the lock fails, Claude doesn't run (stage `claude`). A dir it can't restore fails the manifest check. Removal still works after a panic, because `make_removable` sets every dir to 0700 first (tested).

Tests:
- workspace:
  - a commondir and a `.git` file in the mirror point git nowhere else: no `ext::` command runs, the push reaches the remote and not the attacker, and `push` refuses with "the mirror holds commondir" / ".git";
  - a replace ref hides nothing from `changed_paths`, and `push` refuses;
  - `ext::` never runs in the mirror, even with `protocol.ext.allow=always` in its own config;
  - a symlink in the mirror stops the push;
  - anything added to the mirror fails the check;
  - the mirror is read-only while locked;
  - a locked mirror can still be removed;
- manifest: every kind of change shows; symlinks are recorded, not followed;
- e2e `hostile-repo`: the fake makes the mirror writable again (simulating a stronger bypass) and plants all three. The run fails at `push`, no `ext::` command runs, and nothing reaches the remote, the attacker repo or GitHub.

Mutation checks, each killed: no `GIT_COMMON_DIR`; no replace-ref guard; no protocol limits; no foreign-path check; no symlink check; no config check at push; a manifest that never differs; a lock that does nothing; Claude run unlocked. Removing only `GIT_DIR` survives, because `GIT_COMMON_DIR` alone makes git read the mirror's config, refs and objects. Removing both is caught by the commondir and gitfile tests. `GIT_DIR` stays, so a `.git` file can't redirect the per-worktree files either.

Also:
- **L1.** Git output is redacted in full, then cut to its tail, so a token straddling the cut can't leave its end behind. Output that ends with at least 8 bytes of a token form (git killed mid-write) has that part redacted too. Tested both ways; mutations caught.
- **L2.** Entity neutralising reads the text after `&#` or `&#x` directly and skips any number of leading zeros (tested with 40 zeros, decimal and hex). `&#640;`, `&#x400;` and `&#x40a;` are left alone.
- **L3.** The process-group guard is disarmed after the explicit kill that follows the child's exit, so it can't hit a recycled pgid later. There's no test: it would need a recycled pgid.
- Go's `TestCIConfigPathsLeavesItsInputAlone` has no counterpart, because `ci_config_paths(&[String])` can't change its input.

### Review fixes, round 3 (gap-check)

- **M1.**
  - Big mirror files (packs, over 1 MiB) are now also recorded by `ctime` (seconds and nanoseconds) and `dev`. An unprivileged user can't set `ctime` back, so a same-size rewrite that restores the mtime still shows. Tested with a 2 MiB file: 4 bytes rewritten in place, mtime restored with `File::set_modified`.
  - Every git command on the mirror also gets `-c core.commitGraph=false`.
- **M2.** The mirror is writable again between the post-Claude check and the push, so:
  - `changed_paths` now resolves the branch's mirror ref to a commit (`rev-parse --verify refs/heads/<branch>^{commit}`), diffs the base against that commit, and keeps it. The push sends exactly `<that sha>:refs/heads/<branch>`, and pushing without it is refused.
  - `changed_paths` also records the mirror's manifest, and `check_push` requires it unchanged: "the mirror changed after heinzel checked it (<path>), so heinzel won't push from it".
  - Tests: a branch that moves on to a CI commit after the check still pushes the checked commit; a mirror change after the check stops the push; nothing is pushed before the changes were checked.
- **L1.** Both fetches from the clone run with `--no-recurse-submodules`, `-c gc.auto=0`, `-c maintenance.auto=false`, `-c fetch.fsckObjects=true` and `-c transfer.bundleURI=false`.
- **L2.** `changed_paths` passes `--ignore-submodules=none`, so a submodule (gitlink) change is listed whatever a config says.
- **Accepted limit:** the CI check looks only at the net diff, from base to the pushed commit. A CI file that an intermediate commit adds and a later one removes isn't flagged. Push-triggered workflows run the head commit's configuration, so that's accepted.
- **Mutation checks,** each killed:
  - no `ctime` in the record;
  - pushing the branch ref instead of the checked commit;
  - no manifest re-check at push;
  - pushing without a checked commit.

  L1, L2 and `core.commitGraph=false` have no tests of their own. They're defense in depth behind the manifest and config checks, which already stop a repo config that would turn these settings back on.

### Flaky test fix

`claude::tests::a_leftover_grandchild_neither_delays_nor_outlives_the_run` failed once in a full `cargo test` run. Four full suites run in parallel reproduced it ("took 5.43s"). A temporary probe in `claude::run` showed the cause, across 40 heavily loaded runs:
- the output drain never timed out; it waited 0.2–7 ms after the group kill;
- all the time went into the fake claude itself: `/bin/sh` starting and forking under CPU contention, before it exited.

So the code didn't wait on the grandchild. The test measured the whole run, including the fake's start-up, against a fixed 5s.

I also considered the race where a process forks during `killpg` and the new child escapes the single kill. The probe found no drain timeouts, so I left the code as it is.

Fixes:
- The fake now stamps `exiting` as its last act. The test times the run from that stamp to its return and requires that to stay under `DRAIN_TIMEOUT`, which is what waiting on the grandchild's pipes would cost. It still checks that the grandchild is dead afterwards. Mutation checks: without the group kill after exit, or with a drain that waits out its timeout, the run returns about 5.0s after claude exited and the test fails.
- The claude tests' hang guard (`WAIT_LIMIT`) went from 10s to 30s. Under heavy load even the fake scripts ran past 10s. It guards only against hangs, so the tests prove the same as before.
- `workspace::tests::the_git_runner_kills_commands_after_their_timeout` raced too: a zero timeout against the real `git version`, which can finish before the deadline is polled. It now uses a fake git that hangs and a 200 ms timeout, and checks the exact error.

Checked:
- 40 loaded suite runs (four in parallel) with no slice failures. Two foundation tests, `app::tests`, timed out there on their 5s log wait under that overload. They are 011.01's and untouched.
- 20 clean full `cargo test` runs.
