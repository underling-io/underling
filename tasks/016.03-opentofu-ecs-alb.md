## OpenTofu Infra: ECS + ALB

Part of epic 016. OpenTofu code in `infra/` that deploys the underling image as one ECS Fargate service behind an HTTPS ALB, with Bedrock access through the task role.

### Acceptance Criteria

- **Resources.**
  - A new VPC across two AZs, with the ALB and the task in public subnets.
  - An ALB on 443 with the ACM cert. It redirects 80 to 443 and health-checks `/healthz`. A Route 53 alias record points the domain at it.
  - An ECR repository, and an ECS cluster running a Fargate arm64 service at desired count 1. A deploy stops the old task before it starts the new one, so two writers never overlap.
  - A CloudWatch log group.
  - The two Secrets Manager secrets.
  - A task role allowed exactly the IAM actions and resources docs/event-model.md lists for Bedrock mode (016.01), for every model id the child env names. For an inference profile, that includes its underlying foundation-model ARNs in every region it routes to.
  - An execution role.
- **Inputs.** Variables cover the region, domain, hosted zone and image tag, plus `SENTRY_GITHUB_REPOS`, the investigation timeout, and 016.01's model and region settings, which map 1:1 onto the container env. Outputs give the webhook URL, the ECR repository URL, the log group and the two secret ARNs.
- **State.** The local backend is the default. infra/README.md shows how to switch to an S3 backend through partial backend config, with no edits to the code.
- **Runbook.** infra/README.md walks through a first deploy, in order:
  1. Init, then a targeted apply of everything except the service, the ALB and DNS: ECR, network, cluster, roles, log group, secrets and a probe task definition.
  2. `make image-push`.
  3. The Fargate probe: run the image's sandbox probe (016.02) as a one-off Fargate task. A failure stops the rollout and opens 016.05.
  4. Set the secret values.
  5. Apply the rest: the service, the ALB and DNS.
  6. Point the Sentry integration at the webhook URL.
  7. Roll out a new image tag.
- **Checks.** `make infra-check` runs `tofu fmt -check` and `tofu validate` without AWS credentials. `make check` doesn't run it.

### Notes

- AWS credentials probably aren't available here. Then `tofu validate` is the bar, and the first real apply and the Fargate probe pass to the user. Record that in the implementation notes and the epic.

## Implementation Plan

### TLDR

- **Layout.** A root module in `infra/` with two child modules:
  - `module.base`: network, ECR, cluster, log group, secrets, IAM and the probe task definition.
  - `module.service`: ACM and DNS, the ALB, the service task definition and the service.
- **First apply.** It's `tofu apply -exclude=module.service`. OpenTofu 1.12 has `-exclude`, so there's no `-target` list to keep in sync.
- **Provider.** `hashicorp/aws ~> 6.71`, with the lock file committed.
- **IAM.** The Bedrock grants come from plan-time Bedrock data sources.
- **Deploys.** Min 0 / max 100.
- **Bar.** `make infra-check`. A real apply passes to the user. Expect the Fargate probe to fail (016.02).

### Steps

1. **Root contracts.**
   - `versions.tf`: `required_version = "~> 1.12"` and `hashicorp/aws ~> 6.71`. No `backend` block, so local is the default.
   - Provider: `region = var.aws_region`, with `default_tags { Project = "underling" }`.
   - **Variables.** Each maps 1:1 to the upper-case container env var. `null` leaves the var out.
     - Required: `aws_region` (also the container's `AWS_REGION`), `domain_name`, `hosted_zone_id`, `image_tag` (no default), `sentry_github_repos`, `anthropic_model` and `codex_bedrock_model`.
     - Optional, `null` default: `investigation_timeout`, `anthropic_small_fast_model` and `codex_bedrock_region`.
     - Sizing: `task_cpu = 2048`, `task_memory = 8192` and `ephemeral_storage_gib = 30`.
     - Validation repeats the app's region regex and model-id charset `[A-Za-z0-9._:/-]`.
   - **Outputs (locked, 016.04 and the runbook use them):**
     - `webhook_url` and `base_url`, built from `domain_name` alone so they resolve after the excluded apply;
     - `ecr_repository_url`, `log_group_name`, `github_token_secret_arn`, `sentry_client_secret_arn`;
     - `cluster_name`, `service_name`, `task_role_arn`;
     - `probe_task_definition_arn`, `public_subnet_ids`, `task_security_group_id`;
     - `probe_network_configuration`, the ready-made `jsonencode({awsvpcConfiguration={subnets, securityGroups=[task SG], assignPublicIp="ENABLED"}})` for `aws ecs run-task`.
   - **Fixed names (locals):**
     - cluster, service, container and ECR repo: `underling`;
     - log group: `/ecs/underling`;
     - secrets: `underling/github-token` and `underling/sentry-client-secret`.
2. **`module.base` network.**
   - A VPC at `10.42.0.0/16` with an IGW.
   - Two public /24 subnets in the first two available AZs, with one route table sending `0.0.0.0/0` to the IGW.
   - No NAT; tasks get public IPs.
   - The task SG gets egress-all. Its only ingress, 8080 from the ALB SG, is added in `module.service`.
   - Use the v6 `aws_vpc_security_group_{ingress,egress}_rule` resources.
3. **`module.base` ECR, cluster, logs, secrets.**
   - The ECR repo has `IMMUTABLE` tags and `scan_on_push`.
   - Log retention is 30 days.
   - Two `aws_secretsmanager_secret` with `recovery_window_in_days = 7` and **no** `_version` resources, so values never reach state.
4. **`module.base` IAM.**
   - **Execution role:** `AmazonECSTaskExecutionRolePolicy` plus inline `secretsmanager:GetSecretValue` on exactly the two secret ARNs.
   - **Task role:** trusts `ecs-tasks.amazonaws.com`, with conditions `aws:SourceAccount` and `aws:SourceArn` like `arn:<p>:ecs:<region>:<account>:*`. It has one inline policy and no ECS Exec.
   - **Lookups:** `data.aws_caller_identity`, `data.aws_partition`, `data.aws_bedrock_inference_profiles { type = "SYSTEM_DEFINED" }` and `data.aws_bedrock_foundation_models`.
   - **Classifying each distinct id** in `[anthropic_model, coalesce(small_fast, anthropic_model)]`:
     - **Profile:** its ARN, plus every `models[].model_arn`. For a `global.` id, also the region-less `arn:<p>:bedrock:::foundation-model/<model>`.
     - **Foundation model:** its regional foundation-model ARN.
     - **Neither:** a `lifecycle.precondition` fails the plan, naming the id and the region.
   - **Statements** (docs/event-model.md § AWS needs, exactly):
     1. `InvokeModel` and `InvokeModelWithResponseStream` on the profile and plain-model ARNs.
     2. The same two on the routed foundation-model ARNs, with `StringEquals bedrock:InferenceProfileArn` = the profile ARNs. No `aws:RequestedRegion`.
     3. `GetInferenceProfile` on the profile ARNs, omitted when there are none.
     4. `ListInferenceProfiles` on `*`.
     5. `bedrock-mantle:CreateInference` on `arn:<p>:bedrock-mantle:<codex region>:<account>:project/*`, with `StringEquals bedrock-mantle:Model` = `codex_bedrock_model`.
   - No marketplace actions.
5. **`module.base` probe task definition.**
   - Family `underling-probe`: Fargate, `awsvpc`, LINUX/ARM64, 512/1024, execution role only, no task role.
   - Container `underling`: image `<ecr>:<image_tag>`, `command = ["underling-sandbox-probe"]`, no ports, env or secrets.
   - `awslogs` to `/ecs/underling` with stream prefix `probe`.
   - No `readonlyRootFilesystem`, no extra capabilities, and `initProcessEnabled` the same as the service, so the probe sees the same security settings.
6. **`module.service` ACM, DNS, ALB.**
   - **Certificate:** an ACM cert (DNS validation, `create_before_destroy`). Validation records in `hosted_zone_id` via `for_each`, with `allow_overwrite`. `aws_acm_certificate_validation` gates the 443 listener.
   - **ALB:** internet-facing, in both subnets, with its own SG: 80/443 in from anywhere, 8080 out to the task SG. Add the task SG's ingress rule here. `idle_timeout = 60`, `drop_invalid_header_fields = true`.
   - **Target group:** `ip` targets on HTTP 8080. Health check `/healthz` (matcher 200, interval 15, healthy 2, unhealthy 3, timeout 5), `deregistration_delay = 10`.
   - **Listeners:**
     - 80: 301 to 443.
     - 443: `ELBSecurityPolicy-TLS13-1-2-2021-06`. Default action is a fixed 404, and one rule forwards `/sentry/callback` to the target group, so the public surface is only the webhook.
   - **DNS:** a Route 53 A alias for `domain_name`, with `evaluate_target_health`.
7. **`module.service` task definition and service.**
   - **Task definition:** family `underling`, LINUX/ARM64, sized by the variables, with `ephemeral_storage`. It gets both roles.
   - **Container `underling`:**
     - the image's CMD, port 8080;
     - `environment` per step 1;
     - `secrets` for `GITHUB_TOKEN` and `SENTRY_CLIENT_SECRET`;
     - awslogs with stream prefix `underling`;
     - `stopTimeout = 30`;
     - `linuxParameters.initProcessEnabled = true`, to reap orphans;
     - no container healthCheck.
   - **Service:**
     - FARGATE `LATEST`, `desired_count = 1`;
     - min 0 / max 100;
     - circuit breaker with rollback;
     - `availability_zone_rebalancing = "DISABLED"`;
     - `health_check_grace_period_seconds = 60`;
     - both subnets, the task SG, a public IP;
     - LB on `underling:8080`;
     - `wait_for_steady_state = true`, and `depends_on` the 443 listener.
8. **Lock file, ignores, Makefile.**
   - `tofu providers lock` for darwin_arm64, darwin_amd64, linux_arm64 and linux_amd64; commit `infra/.terraform.lock.hcl`.
   - Gitignore `infra/.terraform/`, `*.tfstate*`, `*.tfvars` (keep `terraform.tfvars.example`), `*.tfbackend` and `*_override.tf`.
   - `make infra-check` is in `.PHONY` and not part of `check`:
     ```
     tofu -chdir=infra init -backend=false -input=false -lockfile=readonly
     tofu -chdir=infra fmt -check -recursive
     tofu -chdir=infra validate
     ```
     Prove it fails on a deliberately misformatted file, then revert that file.
9. **`infra/README.md`.**
   - **Prerequisites:** AWS CLI v2, Docker, jq, a public hosted zone, Bedrock model access enabled (one-time, including Anthropic's form), and Mantle offering the Codex model in its region.
   - Ship `terraform.tfvars.example`.
   - **S3 state:** add a gitignored `backend_override.tf` with `terraform { backend "s3" {} }` and an `s3.tfbackend` (`bucket`, `key`, `region`, `use_lockfile = true`). Then run `tofu init -migrate-state -backend-config=s3.tfbackend`. A backend's type can't come from `-backend-config` alone, which is why the override file exists.
   - **Runbook, in order:**
     1. `tofu init`, then `tofu apply -exclude=module.service`.
     2. `make image IMAGE_TAG=<tag>` and `make image-push ECR_REPOSITORY_URL=$(tofu -chdir=infra output -raw ecr_repository_url) IMAGE_TAG=<tag>`, using the same tag as `image_tag`.
     3. **The probe.**
        - Run `aws ecs run-task --launch-type FARGATE --cluster … --task-definition $(… probe_task_definition_arn) --network-configuration "$(… probe_network_configuration)"`, then `aws ecs wait tasks-stopped`.
        - Read the exit code with `describe-tasks` and the output with `aws logs tail /ecs/underling --log-stream-name-prefix probe/`.
        - Pass: exit 0 and a last line of `sandbox probe: PASS`.
        - `sandbox probe: FAIL`: stop the rollout and open 016.05 (see the epic's "Sandbox vs. Fargate"). Never ship with the sandbox off.
        - Any other failure, such as an image pull error, is an infra issue to fix.
     4. **Secrets.** Create the Sentry internal integration; its client secret is the value. Run `aws secretsmanager put-secret-value` for both secrets via `read -rs` or `file://`, never in argv. A later change needs `aws ecs update-service --force-new-deployment`.
     5. `tofu apply`.
     6. **Sentry webhook.** Set it to `webhook_url` and add the alert-rule action. Check that `curl -sI http://<domain>/` returns 301, and that a GET on `https://<domain>/sentry/callback` reaches underling (405, not the ALB's 404).
     7. **New tag rollout.** `make image image-push`, then `tofu apply -var image_tag=<new>`. Check that the old task's `stoppedAt` is earlier than the new task's `createdAt`. Expect a short window with no receiver. Rolling back means applying the old tag.
   - **Notes:** where the logs are, and destroy only after emptying ECR.
10. **Docs and notes.**
    - docs/event-model.md § Container image: a one-line pointer to infra/README.md.
    - Implementation Notes and the epic record:
      - the `infra-check` result;
      - that the real apply, the probe, the IAM confirmations and the ECS rotation lead time pass to the user;
      - the expected probe outcome.

### Notes

- `tofu init`, `providers lock` and `validate` fail inside the agent sandbox: TLS to the registry (`x509: OSStatus -26276`) and the provider plugin handshake are both blocked there. Run them outside it. They need network but no AWS credentials.
- The Bedrock data sources and the precondition run at plan time, so the operator needs `bedrock:ListInferenceProfiles` and `bedrock:ListFoundationModels`. `validate` reads no data sources.
- Unsettled until a real run: whether the global-profile foundation-model statement works with the `InferenceProfileArn` condition (if `AccessDenied` on `arn:aws:bedrock:::foundation-model/…`, drop it from that statement only), and whether `bedrock-mantle:Model` compares against the plain id.
- Don't add `enableWeakerNestedSandbox` or any other workaround; that's the user's call (epic).

## Implementation Notes

### Verification (2026-11-03, OpenTofu 1.12.1, hashicorp/aws 6.71.0)

- `make infra-check`: **pass** (exit 0), run outside the agent sandbox with network but no AWS credentials. `init -backend=false -lockfile=readonly`, `fmt -check -recursive`, `validate` ("The configuration is valid") and `tofu test` (7 passed, 0 failed).
- **Fails on misformatting:** a misformatted `infra/zz_misformatted.tf` made `make infra-check` exit 2 at `fmt -check` (it names the file); so did a misaligned `=` in `infra/modules/service/main.tf` (so `-recursive` reaches the modules). Both reverted.
- `make check`: **pass** (go vet + `go test -race ./...`), outside the sandbox. It doesn't run `infra-check`.
- The tests catch mutations: with the precondition made always-true and the `global.` region-less ARN branch disabled, two runs failed as expected. The precondition's message reads "Model id(s) us.anthropic.claude-nope-v1:0 are neither a system-defined Bedrock inference profile nor a foundation model in eu-central-1."
- Provider schema (`tofu providers schema -json`): `aws_bedrock_inference_profiles` (`type`, `inference_profile_summaries[].{inference_profile_id, inference_profile_arn, models[].model_arn}`), `aws_bedrock_foundation_models` (`model_summaries[].{model_id, model_arn}`), `aws_ecs_service.availability_zone_rebalancing` and `aws_lb.drop_invalid_header_fields` all exist as planned, so no adaptation was needed.

### Passes to the user (no AWS credentials here)

- The first real apply, following infra/README.md: excluded apply, image push, probe, secrets, full apply, Sentry webhook, tag rollout. Nothing ran `tofu plan`/`apply` against AWS.
- **The Fargate probe.** Expected to **fail** with `bwrap: No permissions to create new namespace`, as 016.02's smoke predicted. Then the rollout stops at runbook step 3 and 016.05 opens; the user decides (epic "Sandbox vs. Fargate"). No workaround was added.
- **IAM points only a real run settles:** whether the global profile's region-less `arn:aws:bedrock:::foundation-model/…` works under the `bedrock:InferenceProfileArn` condition (if `AccessDenied` names it, drop it from that statement only), and whether `bedrock-mantle:Model` compares against the plain id.
- **ECS credential rotation lead time:** whether the task-role endpoint hands out new credentials more than `INVESTIGATION_TIMEOUT` before the old ones expire (docs/event-model.md § Bedrock mode). README.md § Notes repeats it.

### Deviations

- **Review fixes.**
  - **Global profiles:** they also get the source-region foundation-model ARN, as docs/event-model.md § AWS needs lists. The code no longer relies on `models[]` to include it. The mocked global profile now lists only the region-less ARN, so the test proves this.
  - **Runbook step 3:** tails the probe task's own stream (`probe/underling/<task id>`) instead of every stream with the `probe/` prefix.
  - **Runbook step 7:** keeps `image_tag` in `infra/terraform.tfvars` rather than passing `-var`. Otherwise a later plain apply would roll back.

- **`tofu test` in `infra-check`.** Added `infra/tests/` with two test files that plan against a `mock_provider "aws"`, so they make no AWS calls and need no credentials. `base_iam.tftest.hcl` covers the model-id classification (global profile plus foundation model, geo profile across regions, foundation model only, unknown id failing the precondition). `root.tftest.hcl` covers the variables-to-env mapping (nulls left out) and input validation. They are the failing tests that drove the IAM logic, and `make infra-check` runs them as its fourth command.
- **Ordering.** module.base's `execution_role_arn` and `task_role_arn` outputs `depends_on` their policies, so a task never starts before its role can do its job. The service also `depends_on` the task SG's ingress rule from the ALB, not just the 443 listener and the webhook rule.
- **Extra validation** beyond the region and model-id regexes: `domain_name`, `hosted_zone_id`, `image_tag` (tag charset), `sentry_github_repos` (non-empty), `investigation_timeout` (Go duration syntax) and `ephemeral_storage_gib` (21–200).
- **Lock file.** `tofu init` already recorded the registry's `zh:` hashes for every platform; `tofu providers lock` for the four platforms added `h1:` hashes and then reported no further changes.
- **Gitignore.** `*.tfvars` doesn't match `terraform.tfvars.example`, so no negation was needed. Also ignores `.terraform.tfstate.lock.info`.
- **Secrets step.** The runbook reads each value with `read -rs` and passes it to `put-secret-value` through a 0600 temp file (`--secret-string file://…`), so it never reaches argv.
- The container's `environment` and `secrets` are sorted by name, so the task definition doesn't diff on map ordering.

### Assumptions and observations

- Model ids are matched by id, not ARN: an inference-profile or model ARN as `anthropic_model` fails the plan's precondition. The app accepts ARNs (the charset allows them), so this is stricter than the app.
- The mocked tests can't prove what the real `models[]` of a global profile holds; the code adds the region-less ARN itself either way, and `distinct` removes a duplicate.
- The ALB's `/sentry/callback` rule matches the exact path. GET returns underling's 405 (gin `HandleMethodNotAllowed`), which the runbook uses to tell underling from the ALB's 404.
- `aws ecs list-tasks --desired-status STOPPED` in the rollout check only sees tasks stopped within about the last hour.
- Destroying needs an empty ECR repo, and the secrets' 7-day recovery window blocks recreating them under the same names (README.md § Notes).
