## Runner Command and File Contract

Part of epic 018. The runner command, and underling's matching halves: packing a run's input and taking its output into the mirror.

### Acceptance Criteria

- **Command.** The image ships a runner command. It reads everything from its environment: run id, branch, timeout, a GET URL each for the input bundle and the prompt, a PUT URL each for the result and the output bundle, and the Bedrock model and region settings. AWS credentials come from its own environment's default chain, never from underling.
- **Run.** It downloads the inputs, clones the bundle into a fresh work dir on the investigation branch, and runs Claude there with today's flags, plugins and start-up checks (every plugin loaded, no plugin errors, and the permission mode it was started with), but with the sandbox off and without today's `Read` deny rules. Shell commands run unattended; nothing waits for a prompt. The plugin dirs and the `claude` binary come from the image's environment, as today.
- **Result file.** JSON with a format version, a status (`ok`, `failed` or `timeout`), Claude's summary and a failure reason. The runner uploads it whenever it got far enough to know the URLs, including when Claude failed or timed out, and exits 0 only if the upload succeeded.
- **Output bundle.** Holds every branch of the work clone. It is uploaded before the result, so an `ok` result always means the bundle is there. A `failed` or `timeout` result may come without one (no clone yet, bundling failed, the runner was stopped), and underling reads the bundle only for `ok`.
- **Timeout.** Claude is killed, with its process group, after the given timeout; the result says `timeout`.
- **underling's half.** Packing: a bundle of the default branch from the mirror, and the prompt. Taking: the returned bundle's branches land in the mirror the way the work clone's branches do today. A result over 1 MiB, a bundle over `INVESTIGATION_MAX_BUNDLE_BYTES` (default 1 GiB), a result of an unknown version or a bundle git can't verify fails the run as stage `claude`.
- **Test without AWS.** One test runs the whole exchange locally, with the fake Claude and a local HTTP file server in place of S3: pack, runner, take, then today's checks. It covers a fix (PR opened), no commits, a commit on a stray branch, a Claude failure and a timeout.
- **Docs.** docs/event-model.md describes the contract and the runner's isolation, including what Claude can reach without the sandbox.

### Notes

- How Claude Code runs shell commands unattended with the sandbox off (permission mode, allow rules) needs a recorded check against the real CLI, as 016.01 did for Bedrock; the fake Claude can't show it. Bypass mode stays disabled unless nothing else works; then say so in the docs and flag it. If the real CLI can't be run here, flag the check as passed to the user.
- A real Bedrock run needs AWS. If there are no credentials, the local test with the fake Claude is the bar and the real run passes to the user.

## Implementation Plan

Merged from two independent plans (Claude and Codex). They agreed on the shape; where they differed the choice is noted.

### TLDR

Add a second binary, `underling-runner`, built from a new sub-package of the investigate slice. A small contract sub-package holds the env names, object names, result JSON and limits that both halves and 018.02 share. underling's half is a second implementation of the existing `run` interface: it packs a bundle from the mirror, hands it to a launcher, and takes the result and bundle back into the mirror. `investigator.go` does not change. 018.02 plugs its ECS launcher into the same seam; this task's test plugs in a local HTTP file server plus the runner called in-process.

### Steps

1. **Contract package** (leaf sub-package of the slice, imported by the slice, the runner and later 018.02). Lock:
   - **Env, all required by the runner:** `RUNNER_RUN_ID` (`[A-Za-z0-9_-]{1,64}`; underling generates 32 hex chars from crypto/rand), `RUNNER_BRANCH`, `INVESTIGATION_TIMEOUT` (Go duration), `RUNNER_INPUT_BUNDLE_URL` and `RUNNER_PROMPT_URL` (GET), `RUNNER_OUTPUT_BUNDLE_URL` and `RUNNER_RESULT_URL` (PUT), `AWS_REGION`, `ANTHROPIC_MODEL`, `ANTHROPIC_SMALL_FAST_MODEL`, `CODEX_BEDROCK_MODEL`, `CODEX_BEDROCK_REGION`. underling sends the five Bedrock values with defaults already applied. URLs are absolute http(s).
   - **Env mapping:** one function turns the struct into env pairs and one parses it back, so 018.02 builds its container overrides from the same code the runner reads with.
   - **Object names** under `runs/<runId>/`: `input/repo.bundle`, `input/prompt.txt`, `output/repo.bundle`, `output/result.json`.
   - **Result:** `{"version":1,"status":"ok"|"failed"|"timeout","summary":"","reason":""}`, all four keys always present; `failed` and `timeout` carry a non-empty reason. The limit is 1 MiB encoded. The runner cuts `summary` and `reason` to 64 KiB each at a rune boundary before encoding.

2. **`claude` package.**
   - Add an unsandboxed variant of the command, with the same argv as today including `--permission-mode acceptEdits --permission-prompts none`. Candidate settings, subject to step 8: `{"permissions":{"defaultMode":"acceptEdits","disableBypassPermissionsMode":"disable","allow":["Bash","Read","Edit"]},"sandbox":{"enabled":false}}`.
   - Emit no `null` or empty keys: `-p` silently ignores settings that fail validation, which would drop the allow rules while the init check still passes. Pin the JSON with a golden test, and keep today's sandboxed settings assertions.
   - Make the init check compare against the mode the command was built with instead of the hard-coded `acceptEdits`.
   - Keep today's fresh `HOME` and config dir, stdin prompt, model aliases and exact child-env allowlist. No `RUNNER_*` variable reaches Claude's env.
   - Move the Bedrock helpers the runner also needs out of the slice root to somewhere both import: the credentials cache with its "must outlast the timeout" check, the Codex config writer, and the region and model shape rules. Don't copy them.

3. **`workspace` package.**
   - Make the work clone optional and let a bundle be the source of Claude's branches. `StrayBranches` and `NewCommits` fetch from "the source", the clone today or the taken bundle; their logic is otherwise untouched.
   - **Pack:** `git bundle create … HEAD refs/heads/<default>` in the mirror. `HEAD` must be in the bundle so a plain `git clone <bundle>` checks out the default branch. Check the bundle holds no other mirror branch.
   - **Take:** `git bundle verify` in the mirror before any fetch; fetch only `refs/heads/*`.
   - **Runner side:** clone a bundle into `<work>/<run>/repo`, set today's identity config, `checkout -b <branch>`, and later `git bundle create <out> --branches`.
   - `bundle` gets the 10-minute git limit, not the 1-minute default.

4. **Runner package and `cmd/underling-runner`.** The entry point takes getenv, a logger, an optional AWS credentials provider (nil means the default chain) and an HTTP client, and returns the exit code. Main is a thin wrapper with SIGTERM/SIGINT handling. The runner is Bedrock-only. From the image env it reads `PATH`, `CLAUDE_BIN`, `CLAUDE_PLUGIN_DIRS` and `INVESTIGATION_WORK_DIR`, and nothing of underling's other config.
   - **Order:** parse the result URL first, then the rest of the env, download both inputs, make the run dir (`repo`, `home`, `claude-config`, as today), clone, fetch credentials and write the Codex config, run Claude with the given timeout, bundle and upload, upload the result, remove the run dir.
   - **Status:** a Claude timeout gives `timeout`. Any other failure at any step gives `failed` with the error text as `reason`, the text today's Failed event would carry. Success gives `ok` with the summary.
   - **Bundle:** attempted for every status once a clone exists. If bundling or its upload fails, an `ok` becomes `failed`. After a stop signal, skip the bundle and upload only the result on a fresh context of about 20s (ECS kills 30s after SIGTERM). The result upload after a Claude timeout also runs on its own bounded context.
   - **Exit code:** 0 only if the result PUT returned 2xx, whatever the status.
   - **Transfers:** PUT with an explicit `Content-Length` (S3 rejects chunked) and no extra headers. Three attempts on a transport error or 5xx, and a 10-minute cap per transfer.
   - **URL secrecy:** no error, log line or result reason may contain a URL's query string (`*url.Error` prints the whole presigned URL). Test with a server that refuses the PUT.
   - Reject a branch that fails `git check-ref-format --branch`.

5. **underling's half** (slice root).
   - **Seam:** add an exported launcher interface on the slice's params. Its one call receives the contract values without URLs, the input bundle path and the prompt. It runs the runner to its end and returns streams for the result and the output bundle, plus a release hook that the run's `remove()` calls (018.02's cleanup).
   - **Wiring:** nil means in-process, as today. Set without Bedrock mode, construction fails. 018.02 adds `INVESTIGATION_RUNNER` and builds its launcher here.
   - **Remote run:** its clone step makes the mirror and packs; a pack failure is stage `clone`. Its `claude` step launches, reads the result through a reader limited to 1 MiB + 1 and validates it (JSON, version 1, known status). `failed`: an error with the result's reason. `timeout`: a `*claude.TimeoutError` for the configured timeout. `ok`: copy the bundle to the run dir through a reader limited to the max + 1, verify it, return the summary.
   - **Error flattening:** every other error out of this `claude` step (launcher, download, limits, verify) is flattened to text, so a git or net timeout isn't recorded as stage `timeout`.
   - This path never fetches AWS credentials or writes a Codex config on underling's side.
   - **Config:** `INVESTIGATION_MAX_BUNDLE_BYTES`, a positive integer, default 1073741824.

6. **Test** (the slice's external test package, on the existing harness and fake Claude).
   - **Launcher:** an `httptest` server that stores PUTs and serves GETs, and answers 411 to a PUT without `Content-Length`. The launcher calls the runner entry point in-process with only the contract env plus `PATH`, `CLAUDE_BIN` (the test binary), `CLAUDE_PLUGIN_DIRS` and `INVESTIGATION_WORK_DIR`.
   - **Fake Claude:** modes for a commit on another branch, a non-zero exit and a sleep past the timeout. Its settings check gets a runner branch: sandbox off, the allow rules, no deny key.
   - **Cases:** fix gives PullRequestOpened with the branch on the remote; no commits gives NoChanges; a stray branch gives Failed `claude` naming it; a Claude failure gives Failed `claude`; a hang gives Failed `timeout` and kills a descendant process.
   - **Also assert:** the bundle PUT precedes the result PUT; the runner returned 0 in the failure and timeout cases; the fake's recorded env is today's exact Bedrock list with no `RUNNER_*` and no `GITHUB_TOKEN`; the runner removed its run dir; no failure case pushes or opens a PR.
   - **Limit cases**, with a launcher returning canned output: a result over 1 MiB (also when sent chunked, without `Content-Length`), a bundle over a small max, `"version":2`, and a garbage bundle each give Failed `claude`.

7. **Image.** `build-linux-arm64` and `image-context` also build and stage `underling-runner`; the Dockerfile copies it to `/usr/local/bin`. In `smoke.sh`, running `underling-runner` with no contract env must exit non-zero and name a missing variable.

8. **Real-CLI check** (record it in Implementation Notes and in the docs, as 016.01 did).
   - **Where:** preferably in the built image (uid 10001, pinned Claude Code, the image's plugin dirs). Otherwise locally in a scratch dir outside the repo, recording the version.
   - **Setup:** `env -i` with `PATH`, a fresh `HOME` and `CLAUDE_CONFIG_DIR`, and one credential (Bedrock is ideal; an API key with `--bare`, or an OAuth token with `--strict-mcp-config`, shows the same permission behaviour). A fresh git repo with one commit, and the argv and settings exactly as the golden test pins them.
   - **Prompt:** ask for each of these as its own Bash call, reported verbatim: `git add` and `git commit`; a pipeline with `&&` and `$(…)`; `echo x > /tmp/<name>` and `… | tee "$HOME/<name>"`; `wc -l < /etc/hostname`; `cd /tmp && ls`; `curl -sS -o /dev/null -w '%{http_code}' https://example.com`; `go version` and `codex --version`; one command with `run_in_background`; `git status` from a subagent; `echo x > .git/probe`.
   - **Pass:** init shows `acceptEdits`; the final `result` has `is_error:false`; its `permission_denials` holds at most the `.git/probe` write; the commit and the files exist.
   - **Controls:** rerun with `allow` reduced to `["Bash"]`, then with no `allow`; denials must appear. Keep only the rules the controls show are needed.
   - **If commands are still denied:** add narrower rules first, then try `--permission-mode dontAsk` with the same allow rules. Use bypass mode only if nothing else works; then say so in the docs and flag it.
   - **If there is no credential:** ship the candidate settings and hand the check to the user as open.

9. **Docs** (`docs/event-model.md`): the contract from step 1 and the runner's sequence and status rules; `INVESTIGATION_MAX_BUNDLE_BYTES`; the runner binary under Container image; the check from step 8; and a runner isolation section. Claude runs as the runner's user with no sandbox: it can read and write the container's files, read the runner's env through `/proc` (the four presigned URLs included, so it can overwrite the result and bundle itself, which is why underling treats both as untrusted), read the task role's Bedrock-only credentials and reach any HTTPS host. It never has the GitHub token or the Sentry secret.

### Notes

- **Env names.** Codex proposed `INVESTIGATION_*` for the contract variables; `RUNNER_*` is used so they can't be mistaken for underling's own settings.
- **Backstop margin.** Claude gets the full timeout, so download, clone, bundle and upload must fit in 018.02's 2-minute backstop. A large repo finishing near the timeout can lose a good fix to the backstop. Flag at the end of the epic.
- **Accepted divergences.** If Claude deletes every branch, `git bundle create --branches` refuses an empty bundle and the run is Failed `claude`; today it is NoChanges. The work clone also sees only the default branch, not the repo's other branches.
- **Imports.** The slice root must not import the runner package, only the contract. `cmd/underling-runner` imports the runner. `imports_test.go` must allow both.
- **No new failure stage here.** `runner` belongs to 018.02; in this task every launcher error is stage `claude`.

## Implementation Notes

### What was built

- `contract` sub-package: env names, the env mapping in both directions, object names, the result file, the limits, the run id, and the region and model shape rules (underling's own config now uses them from there).
- `claude`: `UnsandboxedCommand`, and an init check that compares against the mode the command was built with.
- `bedrock` sub-package: the credentials cache, the "must outlast the timeout" check and the Codex config writer, moved out of the slice root.
- `workspace`: `NewMirror`, `Pack` and `Take` for underling; `Work` (`NewWork`, `CloneBundle`, `Bundle`) for the runner.
- `runner` sub-package and `cmd/underling-runner`.
- `remote.go`: the `RunnerLauncher` seam on `Params.Runner` and the remote run. `INVESTIGATION_MAX_BUNDLE_BYTES`.
- Tests: `runner_e2e_test.go` (the whole exchange), `remote_e2e_test.go` (canned output), `runner/runner_test.go`, `workspace/bundle_test.go`, `contract/contract_test.go`.
- Image, Makefile, smoke check 4, docs.

### Open: the real-CLI check (plan step 8)

Not run. This environment had no `ANTHROPIC_API_KEY`, no `CLAUDE_CODE_OAUTH_TOKEN` and no working AWS credentials (the `uar-prd` SSO token had expired; no default credentials). The candidate settings shipped as planned:

```json
{"permissions":{"defaultMode":"acceptEdits","disableBypassPermissionsMode":"disable","allow":["Bash","Read","Edit"]},"sandbox":{"enabled":false}}
```

`docs/event-model.md` § Runner isolation says the check is open. It passes to the user, with the steps of plan step 8. If commands are denied, the mode is one constant (`permissionMode` in `claude/command.go`) and the rules one function (`unsandboxedSettings`), both pinned by a golden test.

A real Bedrock run was not possible either, for the same reason.

### Deviations from the plan

- **Launcher returns openers, not streams.** `RunnerOutput` holds `Result` and `Bundle` as functions that open a stream, plus `Release`. With open streams, 018.02 would have to fetch the output bundle before underling has read the result, and a `failed` result may have no bundle. underling calls `Bundle` only after an `ok` result (tested).
- **Chunked result case.** Streams carry no `Content-Length`, so "also when sent chunked" is covered by a result reader that never ends.
- **Run dir before downloads.** The runner makes the run dir first and downloads the bundle into it, instead of downloading first. The bundle needs a place on disk either way.
- **Shape rules live in `contract`,** not with the other Bedrock helpers, so that the contract package imports nothing of the slice.
- **Shared test file server.** `runner/runnertest` is a non-test package, so the runner's own tests and the slice's exchange test share one file server.
- **The runner's own fake claude.** `runner/runner_test.go` has a small fake of its own for the runner's unit tests (stop signal, retries, URL secrecy, limits); the plan only listed the slice-level test.

### Decisions the plan left open

- **Exit code 2** when `RUNNER_RESULT_URL` is missing or invalid; then the log lists every missing variable. Exit 1 when the result upload failed.
- **Stop signal.** The result is `failed` with reason "the runner was stopped before it finished", whatever step was running. The result upload may outlive the signal by 20 seconds; the same mechanism bounds the upload after a Claude timeout (10 minutes).
- **Prompt limit.** The runner reads at most 1 MiB of prompt.
- **Summary redaction.** The runner also replaces the run's URLs and their queries in Claude's summary, since the summary ends up in a public PR and Claude can read the URLs from `/proc`.
- **Retries.** A failed download body is retried like a transport error. Waits are 1s and 2s.
- **A launcher needs Bedrock mode** and then skips the read-path checks and the PATH warnings, which are about the sandbox.
- **Import rule.** `imports_test.go` gained a test that no non-test file of the slice outside `runner/` imports the runner.

### Worth knowing

- `claude.Run` still says "underling shut down while claude was running" when its context is cancelled. The runner never shows that text (it reports the stop itself), so it was left alone.
- TDD was strict for the contract, claude, workspace and config steps. For the runner and `remote.go` the code and its tests were written together; the secrecy and settings assertions were then checked by breaking the code and seeing them fail.
- `make image-smoke` passes checks 1, 2 and 4 on Docker 28.5.1; the sandbox probe fails as recorded before (a warning).
- The timeout tests use a 3s Claude timeout so the fake has time to commit under `-race`; they add about 6s to `make check`.

### After code review

- **underling redacts too.** A result Claude forged in the runner can name the presigned URLs, and the runner's redaction never sees it. `RunnerOutput` gained `Secrets`: the URLs the launcher used. `remote.go` replaces them and their queries in the summary, a `failed` result's reason and every launcher, download and bundle error. The code is `contract.Secrets` and `contract.Redact`, which the runner now uses as well. It matches exact text only: a re-encoded or split URL, part of a query, or a URL inside a commit of the bundle gets through.
- **Redaction moved to where the investigation publishes.** Redacting inside `remote.go`'s Claude step missed what git reads out of the bundle afterwards: a presigned URL's query is a valid branch name and file name, so a stray branch or a changed CI config path could put it into a Failed reason. The run now keeps its secrets and has a `redact` method; the investigator passes every failure reason after the clone, the summary (before it is cut) and the PR title and body through it, and `remote.go` does so for its own cleanup log line. An in-process run's `redact` changes nothing. Content inside commits still can't be redacted.
- **"Cloned" is recorded,** not read off the disk: `Work.Cloned` is true once `git clone` succeeded, so Claude deleting `.git` and reporting success ends `failed` (bundling fails), never `ok` without a bundle.
- **`INVESTIGATION_MAX_BUNDLE_BYTES`** is at most 9223372036854775806, because underling reads one byte past the limit.
- The stop test's watcher goroutine now ends with the test.
