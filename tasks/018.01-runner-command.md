## Runner Command and File Contract

Part of epic 018. The runner command, and underling's matching halves: packing a run's input and taking its output into the mirror.

### Acceptance Criteria

- **Command.** The image ships a runner command. It reads everything from its environment: run id, branch, timeout, a GET URL each for the input bundle and the prompt, a PUT URL each for the result and the output bundle, and the Bedrock model and region settings. AWS credentials come from its own environment's default chain, never from underling.
- **Run.** It downloads the inputs, clones the bundle into a fresh work dir on the investigation branch, and runs Claude there with today's flags, plugins and start-up checks (every plugin loaded, no plugin errors, and the permission mode it was started with), but with the sandbox off and without today's `Read` deny rules. Shell commands run unattended; nothing waits for a prompt. The plugin dirs and the `claude` binary come from the image's environment, as today.
- **Result file.** JSON with a format version, a status (`ok`, `failed` or `timeout`), Claude's summary and a failure reason. The runner uploads it whenever it got far enough to know the URLs, including when Claude failed or timed out, and exits 0 only if the upload succeeded.
- **Output bundle.** Holds every branch of the work clone. It is uploaded before the result, so a result always means the bundle is there.
- **Timeout.** Claude is killed, with its process group, after the given timeout; the result says `timeout`.
- **underling's half.** Packing: a bundle of the default branch from the mirror, and the prompt. Taking: the returned bundle's branches land in the mirror the way the work clone's branches do today. A result over 1 MiB, a bundle over `INVESTIGATION_MAX_BUNDLE_BYTES` (default 1 GiB), a result of an unknown version or a bundle git can't verify fails the run as stage `claude`.
- **Test without AWS.** One test runs the whole exchange locally, with the fake Claude and a local HTTP file server in place of S3: pack, runner, take, then today's checks. It covers a fix (PR opened), no commits, a commit on a stray branch, a Claude failure and a timeout.
- **Docs.** docs/event-model.md describes the contract and the runner's isolation, including what Claude can reach without the sandbox.

### Notes

- How Claude Code runs shell commands unattended with the sandbox off (permission mode, allow rules) needs a recorded check against the real CLI, as 016.01 did for Bedrock; the fake Claude can't show it. Bypass mode stays disabled unless nothing else works; then say so in the docs and flag it. If the real CLI can't be run here, flag the check as passed to the user.
- A real Bedrock run needs AWS. If there are no credentials, the local test with the fake Claude is the bar and the real run passes to the user.
