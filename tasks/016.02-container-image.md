## Container Image

Part of epic 016. A linux/arm64 container image that runs underling in Bedrock mode with all its host prerequisites.

### Acceptance Criteria

- **Contents.** The image holds the underling binary plus what docs/event-model.md § Host prerequisites lists, with claude pinned to the version the docs check against. It also holds:
  - node, for the Codex plugin;
  - Codex, pinned exactly by a build arg, 0.128.0 or later;
  - a pinned Go toolchain with `GOTOOLCHAIN=local`, because the child runs the target repo's tests and the sandbox can't download a toolchain.

  All tools live outside HOME, e.g. in `/usr/local`. docs/event-model.md § Host prerequisites gains "the target repo's toolchain".
- **Plugins.** A make target stages the newest version dir of the Codex and auto-task plugins from `~/.claude/plugins/cache` into the build context, the same rule the system test uses. The image unpacks them in `/opt/underling/plugins`, and their versions are recorded as image labels.
- **Fixed config.** The image sets everything that isn't deployment-specific:
  - a dedicated non-root user and its HOME;
  - the data dir, e.g. `/var/lib/underling/data`;
  - the 0700 work dir, e.g. `/var/lib/underling/work`;
  - `INVESTIGATION_DENY_READ` naming the data dir;
  - `CLAUDE_PLUGIN_DIRS`;
  - `CLAUDE_CODE_USE_BEDROCK=1`.

  Startup logs no "won't run inside the sandbox" warning.
- **Health.** underling answers `GET /healthz` with 200 once it is listening. It's a platform route in the app package, not a slice: no auth, no event store write. It's documented in docs/event-model.md and tested. The image's health check uses it.
- **Make targets.** `make image` builds it. `make image-push` tags it and pushes it to an ECR repository URL passed as a variable.
- **Smoke.** `make image-smoke` runs the image locally with dummy Bedrock config, using only container settings Fargate allows: no `--privileged`, no unconfined seccomp, no capabilities beyond SYS_PTRACE. It checks three things:
  - underling logs "app started";
  - `/healthz` returns 200;
  - the sandbox probe passes.

  If the probe fails under those settings, record it as an early warning about Fargate.
- **Sandbox probe.** The image ships a named probe command. As the underling user, it runs a fixed bwrap invocation that mirrors Claude Code's sandbox: user, net and pid namespaces, a read-only root, one writable bind and `/proc`. It exits non-zero on failure. `make image-smoke` and 016.03's Fargate probe both run it.

## Implementation Plan

### TLDR

- **Go change.** The only one is a platform `GET /healthz` route in `app.Router`.
- **New files.** Everything else lives under `deploy/image/`: a Dockerfile, the `underling-sandbox-probe` script and `smoke.sh`.
- **Image.** `node:22-bookworm-slim` plus:
  - apt git, bubblewrap, socat and curl;
  - claude as the sha256-checked native binary;
  - codex from npm;
  - a sha256-checked Go with `GOTOOLCHAIN=local` written into `$GOROOT/go.env`;
  - the underling binary and the plugins, staged by `make`.
- **Expected probe result: fail.** Both planners measured it on Docker 28.5.1. Under Fargate-allowed settings bwrap fails with "No permissions to create new namespace". Record that as the AC's early warning.

### Steps

1. **`/healthz` (internal/platform/app/run.go `Router`).**
   - Register `GET /healthz` before the state changes. It returns 200 with body `ok`, has no auth and never touches the store. Other methods get 405 from the existing `HandleMethodNotAllowed`.
   - Extend the router test with `GET /healthz` → 200 and `POST /healthz` → 405. Its existing exact-event-count assertion then also proves there's no store write.
   - Add one `Run` test: `GET /healthz` on a started instance with empty `app.Slices{}` returns 200.
2. **`make image-context`.** It wipes and fills `bin/image/`, which is already ignored via `bin/`.
   - It depends on `build-linux-arm64` and copies the binary to `bin/image/underling`. It copies `deploy/image/underling-sandbox-probe` there too.
   - `PLUGIN_CACHE ?= $(HOME)/.claude/plugins/cache`. For `openai-codex/codex` and `auto-task/at`, take the newest version dir via `ls | sort -V | tail -1`, the same order as the system test's `compareVersions`. Copy it to `bin/image/plugins/{codex,at}` and drop `.in_use/` (live pid files). Fail naming the dir if it's missing.
   - Write `bin/image/plugin-versions.mk` with `CODEX_PLUGIN_VERSION := …` and `AT_PLUGIN_VERSION := …`. `make image` passes both as build args.
3. **`deploy/image/Dockerfile`** (context `bin/image`, `--platform linux/arm64`). It's the single place versions are pinned.
   - **Build args:**
     - `CLAUDE_VERSION=2.1.317`, with `CLAUDE_SHA256` taken from `https://downloads.claude.ai/claude-code-releases/<ver>/manifest.json` (linux-arm64);
     - `CODEX_VERSION=0.165.0`;
     - `GO_VERSION=1.27.3` (the repo's go.mod) with `GO_SHA256`;
     - `CODEX_PLUGIN_VERSION` and `AT_PLUGIN_VERSION`, required with no default, so the build fails if either is empty.
   - **Install as root:**
     - claude: download `…/<ver>/linux-arm64/claude`, run `sha256sum -c`, install it to `/usr/local/bin/claude` (0755). Don't use the install script, which installs into HOME.
     - codex: `npm install -g @openai/codex@${CODEX_VERSION}`.
     - Go: unpack to `/usr/local/go`, then replace `GOTOOLCHAIN=auto` with `GOTOOLCHAIN=local` in `/usr/local/go/go.env`. The file edit is load-bearing: the child's env is an exact allowlist, so `ENV` alone never reaches its `go test`.
   - **Build-time assertions:**
     - `claude --version` matches `CLAUDE_VERSION` (run it with a throwaway HOME);
     - `codex --version` is `codex-cli ${CODEX_VERSION}`;
     - `env -i PATH=/usr/local/go/bin:/usr/bin:/bin HOME=/tmp/x go env GOTOOLCHAIN` prints `local`;
     - `bwrap --version` and `socat -V` succeed.
   - **User and dirs:**
     - user `underling`, uid/gid 10001, HOME `/home/underling` (not the base image's `node` user);
     - `/var/lib/underling` root-owned, 0755;
     - `/var/lib/underling/data` and `/var/lib/underling/work` owned by underling, 0700;
     - plugins in `/opt/underling/plugins/{codex,at}`, root-owned and world-readable;
     - the probe at `/usr/local/bin/underling-sandbox-probe`, 0755.
   - **ENV (contract for 016.03):**
     - `HOME=/home/underling`;
     - `PATH=/usr/local/go/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin`;
     - `INVESTIGATION_WORK_DIR=/var/lib/underling/work`;
     - `INVESTIGATION_DENY_READ=/var/lib/underling/data`, exactly that path, because a parent dir would contain the work dir and fail startup;
     - `CLAUDE_PLUGIN_DIRS=/opt/underling/plugins/codex,/opt/underling/plugins/at`;
     - `CLAUDE_CODE_USE_BEDROCK=1`;
     - `GOTOOLCHAIN=local`.
   - **Labels (contract):** `underling.plugins.codex`, `underling.plugins.at`, `underling.claude`, `underling.codex` and `underling.go`.
   - **Runtime:**
     - `USER underling`, `WORKDIR /home/underling`, `EXPOSE 8080`.
     - No ENTRYPOINT. `CMD ["underling","-addr",":8080","-data-dir","/var/lib/underling/data"]`, so 016.03's probe task only overrides the command with `["underling-sandbox-probe"]`.
     - `HEALTHCHECK --interval=10s --timeout=3s --start-period=15s --retries=3 CMD curl -fsS http://127.0.0.1:8080/healthz`.
4. **`deploy/image/underling-sandbox-probe`** (POSIX sh).
   - It fails if uid is 0, or if `bwrap` or `socat` is missing.
   - In a `mktemp -d` dir that's removed on exit, it runs exactly the strict-mode argv of sandbox-runtime's `linux-sandbox-utils.ts`:
     ```
     bwrap --new-session --die-with-parent --unshare-user --unshare-pid --unshare-net \
       --ro-bind / / --bind "$d" "$d" --dev /dev --proc /proc --cap-drop ALL -- /bin/sh -c '<checks>'
     ```
   - The checks inside:
     - a write to `$d` succeeds;
     - a write to `/` fails;
     - `/proc` shows at most 3 numeric pids;
     - `/proc/net/dev` lists only `lo`.
   - bwrap's stderr passes through. The last line is `sandbox probe: PASS` (exit 0) or `sandbox probe: FAIL: <reason>` (exit 1). 016.03 reads it in CloudWatch.
5. **`deploy/image/smoke.sh` via `make image-smoke`** (depends on `image`).
   - Run `docker run -d --network none --cap-add SYS_PTRACE` with nothing else: no `--privileged` and no `--security-opt`. Use this dummy env:
     - `SENTRY_GITHUB_REPOS=1=acme/app`, `GITHUB_TOKEN=dummy`, `SENTRY_CLIENT_SECRET=dummy`;
     - `AWS_REGION=eu-central-1`, `ANTHROPIC_MODEL=global.anthropic.claude-sonnet-4-5-20250929-v1:0`, `CODEX_BEDROCK_MODEL=openai.gpt-oss-120b`;
     - dummy `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`.
   - Always `docker rm -f` on exit.
   - Three checks:
     1. Within 30s the log shows `"msg":"app started"`, and no line contains `won't run inside the sandbox`.
     2. `docker exec … curl -fsS http://127.0.0.1:8080/healthz` returns 200.
     3. `docker exec … underling-sandbox-probe`.
   - Print one PASS/FAIL line per check.
   - Checks 1–2 failing exits 1. A probe failure prints `WARNING: sandbox probe failed under Fargate-allowed container settings; Fargate likely can't run the sandbox (see 016.03/016.05)` and exits 0, unless `SMOKE_REQUIRE_PROBE=1` is set, which makes it fatal.
6. **Makefile.**
   - Variables (contract): `IMAGE ?= underling`, `IMAGE_TAG ?= $(shell git rev-parse --short=12 HEAD)`, `ECR_REPOSITORY_URL` (required by `image-push`) and `PLUGIN_CACHE`.
   - `image`: `image-context`, then `docker build --platform linux/arm64 -f deploy/image/Dockerfile` with the plugin build args, `-t $(IMAGE):$(IMAGE_TAG) bin/image`.
   - `image-push`:
     1. Fail with a usage message if `ECR_REPOSITORY_URL` is empty.
     2. `aws ecr get-login-password --region <region parsed from the URL host> | docker login --username AWS --password-stdin <registry host>`.
     3. Tag and push `$(ECR_REPOSITORY_URL):$(IMAGE_TAG)`, then print the ref.
   - `check` stays Docker-free. Add the new targets to `.PHONY`.
7. **docs/event-model.md.**
   - Document `/healthz` in the top section.
   - Host prerequisites gains:
     - `node`, for the Codex plugin;
     - "the target repo's toolchain, outside HOME, working offline", with the `$GOROOT/go.env` reason;
     - that the sandbox has no module proxy access, so a target repo's tests can only use modules already present.
   - A new "Container image" subsection covers:
     - paths, ENV, user, labels and make variables;
     - the probe's invocation and output contract;
     - the smoke settings and the recorded probe result;
     - "don't set `readonlyRootFilesystem`": `/tmp`, HOME and `/var/lib/underling` must be writable.

### Notes

- **Measured with bwrap 0.8.0 on Docker 28.5.1:**

  | Docker settings | Result |
  | --- | --- |
  | Default seccomp, with or without `SYS_PTRACE` | `No permissions to create new namespace` |
  | `seccomp=unconfined` | `Can't mount proc` |
  | `seccomp=unconfined` + `systempaths=unconfined` | PASS |
  | `--bind /proc /proc` (Claude Code's `enableWeakerNestedSandbox`) under unconfined seccomp | PASS |

  Even ECS on EC2 would need unconfined seccomp plus unmasked `/proc`, or the weaker nested sandbox. That's a security decision, so flag it on the epic. Don't enable `enableWeakerNestedSandbox` here: it lets sandboxed commands read `/proc/<underling pid>/environ`, which holds `GITHUB_TOKEN`.
- The probe checks namespaces and mounts only. Claude Code's own sandbox only starts inside a model turn, which dummy credentials can't produce.
- Native claude may try to auto-update into the child HOME, and `DISABLE_AUTOUPDATER` can't reach the child env. Watch for pin drift in 016.04.
- Docker commands run outside the agent sandbox.

## Implementation Notes

### Smoke result (`make image-smoke`, 2026-11-03)

Docker 28.5.1 (Docker Desktop, arm64), image `underling:1eea86073347` (rebuilt after the review fixes; first run on `underling:30dd708f3042` gave the same output), bubblewrap 0.8.0. Exit 0, output:

```
PASS: app started
PASS: /healthz returned 200
bwrap: No permissions to create new namespace, likely because the kernel does not allow non-privileged user namespaces. See <https://deb.li/bubblewrap> or <file:///usr/share/doc/bubblewrap/README.Debian.gz>.
sandbox probe: FAIL: bwrap exited 1
FAIL: sandbox probe
WARNING: sandbox probe failed under Fargate-allowed container settings; Fargate likely can't run the sandbox (see 016.03/016.05)
```

- **Probe: FAIL**, as both planners predicted. This is the AC's early warning: under Fargate-allowed settings (default seccomp, only `SYS_PTRACE` added) bwrap can't create the user namespace. `SMOKE_REQUIRE_PROBE=1` turns it into exit 1 (checked).
- The probe itself was validated under looser local settings (re-checked with the review-fix probe, see below): `seccomp=unconfined` alone fails with `Can't mount proc on /newroot/proc: Operation not permitted`; `seccomp=unconfined` + `systempaths=unconfined` gives `sandbox probe: PASS` (both `--network none` and the default bridge). Variants with `--unshare-net` removed, `--unshare-pid` removed, `--bind / /` instead of `--ro-bind`, and a read-only `$d` each fail with the matching reason. As root it fails with "running as root".
- The Docker `HEALTHCHECK` reported `healthy` after ~6s. The startup log is the single `app started` line, with no sandbox warning.

### Other verification

- `make check`: pass (go vet + `go test -race ./...`), run outside the sandbox.
- `make image`: builds. Assertions pass: claude `sha256sum -c` OK and `2.1.317 (Claude Code)`, `codex-cli 0.165.0`, Go tarball checksum OK, `go env GOTOOLCHAIN` = `local` and `GOVERSION` = `go1.27.3` with an empty env, `bubblewrap 0.8.0`. Labels: `underling.claude=2.1.317`, `underling.codex=0.165.0`, `underling.go=1.27.3`, `underling.plugins.codex=1.0.6`, `underling.plugins.at=0.1.0`. In the image: uid 10001, data/work dirs 0700 underling, plugins root-owned 0755, node v22.23.4.
- A `docker build` without the plugin build args fails at the version check, as required.
- `make image-push` without `ECR_REPOSITORY_URL` prints the usage message and fails; with a non-ECR host it fails with "can't parse the region". Nothing was pushed, and `aws` was never invoked.
- Pins came from `https://downloads.claude.ai/claude-code-releases/2.1.317/manifest.json` (linux-arm64 checksum) and `https://go.dev/dl/?mode=json&include=all` (go1.27.3 linux-arm64).
- The final image is `underling:1eea86073347`; its tag is the commit `make image` ran at, before the notes commit. Its content matches HEAD. Smoke containers and the earlier `underling:30dd708f3042` were removed. The pre-existing `underling:latest` (2026-10-25) wasn't touched.

### Deviations

- **Probe checks.** The plan's "`/proc/net/dev` lists only `lo`" failed under the PASS settings: on Docker Desktop's kernel a new net namespace also holds down fallback tunnel devices (`tunl0`, `gre0`, `sit0`, ...). And "at most 3 pids" passed even without `--unshare-pid`, because a near-empty container has that few pids anyway. So the probe now compares the pid and net namespace ids with the outer ones, keeps the ≤3 pid count, and replaces the interface list with "`/proc/net/route` has no routes". The read-only root check writes to `/` and to `$d`'s parent (`/tmp`). A write to `/` alone fails for a non-root user even without `--ro-bind`.
- **Docs layout.** "Container image" is a top-level `##` section (with `### Sandbox probe` and `### Smoke`), not part of the investigate slice's `####` subsections, because it covers the whole app.
- **Makefile.** `image` runs `image-build` in a sub-make so the build reads the `plugin-versions.mk` that `image-context` just wrote (`-include` is read before the recipe runs). `image-push` pushes the already built `$(IMAGE):$(IMAGE_TAG)` and doesn't depend on `image`.
- The Dockerfile also asserts `go env GOVERSION`, and installs `ca-certificates`, which the slim base lacks and `curl`/`git` need.

### Observations and follow-ups

- **Fargate (epic).** The smoke result says Fargate most likely can't run the sandbox. Even ECS on EC2 would need unconfined seccomp plus unmasked `/proc`, or `enableWeakerNestedSandbox`, which exposes `/proc/<underling pid>/environ` (`GITHUB_TOKEN`) to sandboxed commands. That's a security decision for the epic/016.05. 016.03's Fargate probe task (command `["underling-sandbox-probe"]`) should confirm it on real Fargate.
- **Codex PATH aliases.** At build, `codex --version` warned "Refusing to create helper binaries under temporary dir /tmp" (the throwaway HOME). At runtime the child HOME is under `/var/lib/underling/work`, so Codex will create them there. That's harmless, but watch for it in 016.04.
- **Image size** is about 1.9 GB unpacked (claude's native binary alone is ~330 MB, plus Go and node). A slimmer image is possible later.
- **Native claude auto-update** may still try to write into the child HOME (plan note). Watch for pin drift in 016.04.

### Review fixes

- **Image tag.** `IMAGE_TAG` now defaults to `git describe --always --dirty --abbrev=12`, so an image built from a tree with uncommitted changes is tagged `<commit>-dirty`. `image-push` refuses a `-dirty` tag unless `IMAGE_TAG`'s origin is the command line or the environment. Checked against a copy of the Makefile with the push stubbed out: the default dirty tag is refused; `IMAGE_TAG=foo-dirty` on the command line or in the environment, and a clean tag, go through. This supersedes the plan's `git rev-parse --short=12 HEAD`.
- **Base image.** `FROM node:22.23.4-bookworm-slim@sha256:4b150b48b4116e2a22f2c39cc27025fbf4f153e2078fd3b14d159fdb5c7279da`, the multi-arch index digest from `docker buildx imagetools inspect`. The floating `node:22-bookworm-slim` had moved to that same index since the first build (a Debian rebuild; Node is still 22.23.4). A `BWRAP_VERSION` build arg (default 0.8.0) makes the build fail unless `bwrap --version` prints `bubblewrap ${BWRAP_VERSION}`, and the image gets a `underling.bwrap` label. Debian's `git`, `socat` and `curl` still come from whatever bookworm ships at build time.
- **Smoke.** The container is named `underling-smoke-$$` and removed by name in the EXIT trap; `trap 'exit 130' INT TERM HUP` runs that cleanup on signals too. Checked: a `TERM` mid-run exits 130 and leaves no container; `SMOKE_REQUIRE_PROBE=1` exits 1 and leaves none.
- **Probe.** The argv adds `--disable-userns` and `--tmpfs "$HOME"` (standing in for a deny-read path) and runs `bash` instead of `/bin/sh`. New checks inside: `HOME` is a tmpfs mount (from `/proc/self/mountinfo`) and empty, and a nested `unshare -U true` fails. The docs now say it mirrors claude 2.1.317's Linux sandbox invocation rather than the exact strict-mode argv. Results (`underling:probe-test`, same content as the final image):

  | Docker settings | Probe |
  | --- | --- |
  | Default seccomp + `SYS_PTRACE`, `--network none` (the smoke) | FAIL: `bwrap: No permissions to create new namespace` |
  | `seccomp=unconfined` | FAIL: `bwrap: Can't mount proc on /newroot/proc: Operation not permitted` |
  | `seccomp=unconfined` + `systempaths=unconfined` (`--network none` and bridge) | PASS |
  | same, probe without `--disable-userns` | FAIL: `unshare -U succeeded, want nested user namespaces disabled` |
  | same, probe without `--tmpfs "$HOME"` | FAIL: `/home/underling is mounted as nothing, want the tmpfs over it` |
  | as root | FAIL: `running as root; run as the underling user` |
- **Docs.** The writable-root note now names `/var/lib/underling/data` and `/var/lib/underling/work` rather than `/var/lib/underling`.
- `make check` passes after the fixes (run outside the sandbox).

### Fix-review fixes

- **Tag.** Back to `git rev-parse --short=12 HEAD`, plus `-dirty` whenever `git status --porcelain` is non-empty. `git describe --dirty` missed untracked files and would switch to tag names once the repo has tags.
- **Probe.** It canonicalises HOME before the tmpfs and the mountinfo check, keeps the writable bind in `/tmp` outside HOME, and requires the nested `unshare -U` to fail with ENOSPC, the `--disable-userns` signature. Any other failure no longer counts as a pass.
- **Smoke.** The container name is unique per run (`underling-smoke-<pid>-<epoch>`). The EXIT trap removes only a container this run created. HUP, INT and TERM exit 129, 130 and 143.
