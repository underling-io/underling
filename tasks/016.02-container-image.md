## Container Image

Part of epic 016. A linux/arm64 container image that runs heinzel in Bedrock mode with all its host prerequisites.

### Acceptance Criteria

- **Contents.** The image holds the heinzel binary plus what docs/event-model.md § Host prerequisites lists, with claude pinned to the version the docs check against. It also holds:
  - node, for the Codex plugin;
  - Codex, pinned exactly by a build arg, 0.128.0 or later;
  - a pinned Go toolchain with `GOTOOLCHAIN=local`, because the child runs the target repo's tests and the sandbox can't download a toolchain.

  All tools live outside HOME, e.g. in `/usr/local`. docs/event-model.md § Host prerequisites gains "the target repo's toolchain".
- **Plugins.** A make target stages the newest version dir of the Codex and auto-task plugins from `~/.claude/plugins/cache` into the build context, the same rule the system test uses. The image unpacks them in `/opt/heinzel/plugins`, and their versions are recorded as image labels.
- **Fixed config.** The image sets everything that isn't deployment-specific:
  - a dedicated non-root user and its HOME;
  - the data dir, e.g. `/var/lib/heinzel/data`;
  - the 0700 work dir, e.g. `/var/lib/heinzel/work`;
  - `INVESTIGATION_DENY_READ` naming the data dir;
  - `CLAUDE_PLUGIN_DIRS`;
  - `CLAUDE_CODE_USE_BEDROCK=1`.

  Startup logs no "won't run inside the sandbox" warning.
- **Health.** heinzel answers `GET /healthz` with 200 once it is listening. It's a platform route in the app package, not a slice: no auth, no event store write. It's documented in docs/event-model.md and tested. The image's health check uses it.
- **Make targets.** `make image` builds it. `make image-push` tags it and pushes it to an ECR repository URL passed as a variable.
- **Smoke.** `make image-smoke` runs the image locally with dummy Bedrock config, using only container settings Fargate allows: no `--privileged`, no unconfined seccomp, no capabilities beyond SYS_PTRACE. It checks three things:
  - heinzel logs "app started";
  - `/healthz` returns 200;
  - the sandbox probe passes.

  If the probe fails under those settings, record it as an early warning about Fargate.
- **Sandbox probe.** The image ships a named probe command. As the heinzel user, it runs a fixed bwrap invocation that mirrors Claude Code's sandbox: user, net and pid namespaces, a read-only root, one writable bind and `/proc`. It exits non-zero on failure. `make image-smoke` and 016.03's Fargate probe both run it.
