## Post-Deploy System Test

Part of epic 016. A system test run against the deployed heinzel. It posts a signed Sentry alert to the public webhook and checks, in a real GitHub repo, that heinzel fixed task 013's go-version bug.

### Acceptance Criteria

- **Opt-in.** Its own package, behind its own build tag, run by `make postdeploy-test`.
- **Inputs.** Env vars give the webhook base URL, `SENTRY_CLIENT_SECRET`, the Sentry project id the deployment maps to the target repo, the target repo (`owner/name`), and a GitHub token for the test itself.
- **Reset.** The target repo is a throwaway repo the user owns. Before posting, the test force-pushes its default branch to go-version at c6a3b57's parent, as 013 serves it. It deletes every `heinzel/*` branch and closes every open PR from one.
- **Precondition.** As in 013, on a local clone of the reset branch.
- **Alert.** The test posts a signed `event_alert` to `<base>/sentry/callback` describing the real panic, with event and issue ids unique per run, and gets 200 `{"status":"recorded"}`.
- **Wait.** It polls GitHub, for at most 45 minutes, until a draft PR from `heinzel/sentry-<issueId>` appears. A timeout fails and names the log group to look at.
- **Verdict and comparison.** As in 013, on a fresh clone of the pushed branch from GitHub.
- **Shared helpers.** 013's alert, precondition, verdict and comparison helpers move into an untagged non-test package under `internal/systemtest`, used by both tests. `make system-test` keeps its behaviour.
- **Docs.** infra/README.md says how to run the test after a deploy. It also covers what the throwaway repo needs:
  - Actions disabled, so go-version's workflows don't run on resets and pushes;
  - the test token is a fine-grained PAT for that repo only, with contents, pull-requests and workflows write;
  - the deployed heinzel's token keeps lacking the workflow scope.

### Notes

- A real run needs a deployed stack. If there isn't one, compiling under the tag and a dry run up to the missing-input check are the bar. The real run passes to the user.
