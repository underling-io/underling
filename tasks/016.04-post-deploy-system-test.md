## Post-Deploy System Test

Part of epic 016. A system test run against the deployed underling. It posts a signed Sentry alert to the public webhook and checks, in a real GitHub repo, that underling fixed task 013's go-version bug.

### Acceptance Criteria

- **Opt-in.** Its own package, behind its own build tag, run by `make postdeploy-test`.
- **Inputs.** Env vars give the webhook base URL, `SENTRY_CLIENT_SECRET`, the Sentry project id the deployment maps to the target repo, the target repo (`owner/name`), and a GitHub token for the test itself.
- **Reset.** The target repo is a throwaway repo the user owns. Before posting, the test force-pushes its default branch to go-version at c6a3b57's parent, as 013 serves it. It deletes every `underling/*` branch and closes every open PR from one.
- **Precondition.** As in 013, on a local clone of the reset branch.
- **Alert.** The test posts a signed `event_alert` to `<base>/sentry/callback` describing the real panic, with event and issue ids unique per run, and gets 200 `{"status":"recorded"}`.
- **Wait.** It polls GitHub, for at most 45 minutes, until a draft PR from `underling/sentry-<issueId>` appears. A timeout fails and names the log group to look at.
- **Verdict and comparison.** As in 013, on a fresh clone of the pushed branch from GitHub.
- **Shared helpers.** 013's alert, precondition, verdict and comparison helpers move into an untagged non-test package under `internal/systemtest`, used by both tests. `make system-test` keeps its behaviour.
- **Docs.** infra/README.md says how to run the test after a deploy. It also covers what the throwaway repo needs:
  - Actions disabled, so go-version's workflows don't run on resets and pushes;
  - the test token is a fine-grained PAT for that repo only, with contents, pull-requests and workflows write;
  - the deployed underling's token keeps lacking the workflow scope.

### Notes

- A real run needs a deployed stack. If there isn't one, compiling under the tag and a dry run up to the missing-input check are the bar. The real run passes to the user.

## Implementation Plan

### TLDR

- **Shared helpers.** Move 013's go-version helpers into an untagged, non-test package `internal/systemtest/upstreamfix`, and rewire the `system`-tagged test onto it without changing its behaviour.
- **New test.** Add `internal/systemtest/postdeploy`, tag `postdeploy`, run by `make postdeploy-test`. It:
  1. checks its inputs with no network;
  2. guards, then resets, the throwaway repo;
  3. runs the precondition on a clone from GitHub;
  4. posts a signed alert with per-run ids;
  5. polls for the draft PR, up to 45m;
  6. runs the verdict and comparison.
- **Docs.** infra/README.md gets a section.

### Steps

1. **`internal/systemtest/upstreamfix`** (no build tag, no `_test.go`, imports `testing` only for `testing.TB`). Locked API:
   ```go
   const (URL = "https://github.com/hashicorp/go-version.git"; Fix = "c6a3b5735e33d3e07a9cfbc8343e84b69d471b80"; RegressionTest = "TestCoreZeroValue")
   type Upstream struct{ Dir, FixedTest, Parent string } // Parent = full SHA of Fix^
   func Clone(t testing.TB) Upstream
   func RequireBugReproduces(t testing.TB, dir string, u Upstream) // Fatal unless "--- FAIL: TestCoreZeroValue"
   func CheckFix(t testing.TB, dir string, u Upstream)             // Errorf if the test or ./... fails
   func LogComparison(t testing.TB, dir string, u Upstream)
   type Alert struct{ EventID, IssueID string; Project int64 }
   func PostAlert(t testing.TB, callbackURL, secret string, a Alert) // 013's payload and HMAC; Fatal unless 200 {"status":"recorded"}
   func Git(t testing.TB, dir string, args ...string) string
   func GoTest(dir string, args ...string) (string, error)         // -count=1, GOTOOLCHAIN=local
   ```
   - **What stays in `upstreamfix_test.go`:**
     - the credentials and Bedrock checks, the tool checks, the plugin copies;
     - `serveParentOfFix`, now taking `u`;
     - the underling process, the fake GitHub;
     - 013's fixed ids.
   - **Flow and behaviour:** the flow and assertions are unchanged. The only behaviour change is that `PostAlert` also requires `"recorded"`, which a fresh store always answers.
   - **Check:** `go vet ./...`, `go vet -tags system ./internal/systemtest/...` and `go test -tags system -run '^$' ./internal/systemtest` all pass. `make system-test` without credentials still fails at 013's credential message.
2. **Package `internal/systemtest/postdeploy`.**
   - `doc.go` is untagged. It says the test force-pushes the named repo and is run by `make postdeploy-test`.
   - `postdeploy_test.go` has `//go:build postdeploy` and holds `TestDeployedUnderlingFixesARealUpstreamBug`.
   - **Inputs (locked):**
     - `POSTDEPLOY_BASE_URL`: absolute `https` with no path beyond `/`, trailing `/` trimmed. http is refused because the 301 would turn the POST into a GET.
     - `SENTRY_CLIENT_SECRET`.
     - `POSTDEPLOY_SENTRY_PROJECT_ID`: a positive integer.
     - `POSTDEPLOY_GITHUB_REPO`: `owner/name`; `hashicorp/go-version` is refused.
     - `POSTDEPLOY_GITHUB_TOKEN`: never `GITHUB_TOKEN`.
     - Optional `POSTDEPLOY_LOG_GROUP`, default `/ecs/underling`, used in failure messages only.
   - All problems are collected into one `t.Fatal` naming each variable, before any clone or HTTP call. `git` and `go` must be on PATH.
   - **Dry-run bar:** `make postdeploy-test` with nothing set fails quickly, names all five, and makes no network call.
3. **GitHub access (test-local).**
   - **API:** `net/http` against the constant `https://api.github.com`, with `Bearer`, `Accept: application/vnd.github+json` and `X-GitHub-Api-Version: 2022-11-28`. Errors show method, path, status and body, never the token.
   - **Authenticated git** runs with `os.Environ()` plus `GIT_TERMINAL_PROMPT=0`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null`, and `GIT_CONFIG_COUNT/KEY_0/VALUE_0` = `http.https://github.com/.extraHeader` / `Authorization: Basic base64(x-access-token:<token>)`. The token is never in argv or a URL, and its plain and base64 forms are redacted from failure output.
4. **Guard, then reset, in this order.**
   1. `GET /repos/{repo}`. Refuse if it's archived, a fork, or `permissions.push != true`. Take `default_branch` from it.
   2. `git ls-remote`. Refuse without changing anything if any ref exists other than `HEAD`, `refs/heads/<default>`, `refs/heads/underling/*` and `refs/pull/*`. Tags and other branches would reach underling's `clone --bare` and could hold the fix. If there are any heads, `GET /repos/{repo}/commits/{u.Parent}` must answer 200, meaning the repo already holds go-version's history; an empty repo skips this.
   3. Close open PRs. Page through `GET /pulls?state=open&per_page=100`. For each PR whose `head.repo.full_name == repo` and whose `head.ref` starts with `underling/`, send `PATCH {"state":"closed"}`.
   4. From `u.Dir`, run `git push --force --atomic --no-verify --no-follow-tags https://github.com/{repo}.git <u.Parent>:refs/heads/<default>`, plus `:refs/heads/underling/…` for each such branch.
   5. Run `ls-remote` again. Require exactly `HEAD` and `refs/heads/<default>` at `u.Parent`, plus any `refs/pull/*`.
5. **Precondition, alert, wait, verdict.**
   1. **Precondition.** Do an authenticated clone, assert `HEAD == u.Parent`, then call `RequireBugReproduces`.
   2. **Ids.** `IssueID` is the decimal `time.Now().UnixMilli()`, so the branch is `underling/sentry-<IssueID>` as-is. `EventID` is 32 lowercase hex characters from `crypto/rand`. Both are unique per run because the deployed store dedupes events and issues for the task's whole life.
   3. **Alert.** `PostAlert(t, base+"/sentry/callback", …)`, then log both ids.
   4. **Wait.**
      - The deadline is the earlier of post + 45m and `t.Deadline() − 3m`.
      - Every 30s, `GET /pulls?state=all&head=<owner>:underling/sentry-<IssueID>`.
      - A 5xx, 429, rate-limit 403 or network error: log it and retry. Any other non-200: fail.
      - Log "still waiting" every ~5m.
      - When a PR appears, require `draft == true`, `state == "open"`, `base.ref == default_branch` and `head.repo.full_name == repo`. Otherwise fail and list the fields.
      - On timeout, fail naming the repo, branch, 45m and the issue id, with `aws logs tail <log group> --since 1h --filter-pattern '"<IssueID>"'` and a hint that an unmapped project id ends as Skipped `unmapped`.
   5. **Verdict.** Do a fresh authenticated `clone --branch`, assert `HEAD == pr.head.sha`, then call `CheckFix` and `LogComparison`. Log the PR URL. The PR stays open; the next reset closes it.
6. **Makefile.**
   - Add `postdeploy-test` to `.PHONY`, with recipe `go test -tags postdeploy -timeout 60m -v -count=1 ./internal/systemtest/postdeploy`.
   - The comment lists the vars and says the test costs Bedrock tokens and force-pushes the repo.
   - `check` and `system-test` stay unchanged.
7. **infra/README.md "Post-deploy system test" section**, after the runbook.
   - **The throwaway repo:**
     - a new repo you own, not a fork, empty or touched only by this test;
     - Actions disabled, so go-version's workflows (which the history may contain) don't run;
     - no branch protection or rulesets on the default branch;
     - no tags or other branches;
     - mapped in `sentry_github_repos`.
   - **The deployed `GITHUB_TOKEN`:** contents and PR write on the repo, still without the workflow scope.
   - **The test token:** a fine-grained PAT for that repo only, with Contents, Pull requests and Workflows read/write.
   - **Running it:** the run command with `$(tofu -chdir=infra output -raw base_url)` and `log_group_name`. Read the secrets with `read -rs`.
   - **Expectations:** about 50m and destructive. On timeout, read the logs.

### Notes

- The bar here:
  - `go vet` passes untagged and under both tags;
  - the tagged test compiles (`-run '^$'`);
  - the dry run fails on inputs;
  - `make check` stays green.

  The real run passes to the user. Record that in Implementation Notes and the epic.
- The guard is beyond the AC on purpose. A mistyped repo with a broad token must never get its default branch rewritten.
- `refs/pull/*` survive and can contain old fixes. That's harmless, because `clone --bare` fetches only heads and tags.
- Unverified until a real run:
  - whether underling's push of a branch whose history includes `.github/workflows` (already on the default branch) works without the workflow scope;
  - whether c6a3b57^ contains workflows at all.

  If not, the run ends at stage `push` and the test times out.
- An early underling failure (e.g. the expected Fargate sandbox failure) shows up only as the timeout with the log pointer. That's per the AC; don't add CloudWatch reads.

## Implementation Notes

- **Not run for real.** There is no deployed stack and no GitHub or Sentry token here, so the real run passes to the user (infra/README.md § Post-deploy system test). Nothing was run against GitHub; no repo was touched.
- **Verification (all run outside the sandbox, which blocks port binding and the Go build cache):**
  - `make check` passes, and with it the new untagged unit tests in `internal/systemtest/postdeploy`.
  - `go vet ./...`, `go vet -tags system ./internal/systemtest/...` and `go vet -tags postdeploy ./internal/systemtest/...` pass.
  - `go test -tags system -run '^$' ./internal/systemtest` and `go test -tags postdeploy -run '^$' ./internal/systemtest/postdeploy` compile and pass.
  - `env -i PATH=$PATH HOME=$HOME make postdeploy-test` fails in 0.00s at the input check, naming all five variables, before any clone or HTTP call.
  - `env -i PATH=$PATH HOME=$HOME make system-test` still fails at 013's credential check (`OPENAI_API_KEY must be set: the child runs Codex`), before any clone.
- **Deviation: the pure checks live in an untagged `checks.go`.** The plan had only `doc.go` untagged. Input parsing, the ref guard (`unexpectedRefs`, `underlingBranches`, `hasHeads`, `checkResetRefs`), token redaction, the extra header, retry classification, the wait deadline, the PR field check and the timeout message are pure functions in `checks.go`, unit-tested in the untagged `checks_test.go`. So `make check` covers them, with no network. The I/O (GitHub API, authenticated git, the flow) stays in the `postdeploy`-tagged `postdeploy_test.go`.
- **Fix in the shared comparison.** 013 logged `git diff c6a3b57^ HEAD` in the clone of Claude's branch, which doesn't hold c6a3b57, so that call would have failed the test after the verdict. `LogComparison` diffs against `u.Parent`, the parent's full SHA, which the branch clone holds. 013 never had a real run, so this was never hit.
- **Canonical repo name.** After `GET /repos/{repo}`, the test uses the API's `full_name` for every later comparison (`head.repo.full_name`, PR filter), so a differently-cased `POSTDEPLOY_GITHUB_REPO` still matches.
- **Extra input checks.** Beyond the plan: the base URL must have no user info, query or fragment; the repo check is case-insensitive against `hashicorp/go-version` and rejects `.`/`..` names; the token must not contain whitespace or control characters (it goes into a header).
- **Guard order.** `GET /repos` runs before the upstream clone, so a wrong repo or token fails fast; the `ls-remote` guard and the commit check follow the clone, as they need `u.Parent`.
- **Still unverified until a real run** (from the plan): whether underling's push without the workflow scope works on a history that already holds `.github/workflows`, and whether c6a3b57^ has workflows at all. If not, the run ends at stage `push` and the test times out with the log pointer.

### Review fixes

- **Default-branch guard.** A repo with branches is reset only if its default branch sits exactly on go-version's parent of the fix, as every earlier reset leaves it. `/commits/{sha}` alone answered 200 for commits reachable through `refs/pull/*` or the fork network, so a go-version mirror with the user's own work on `main` would have been force-pushed.
- **Lease.** The push uses `--force-with-lease` on the default branch at the SHA the guard saw, so a change during PR closing fails the push.
- **Secrets out of the env.** After the input check, the test clears `POSTDEPLOY_GITHUB_TOKEN` and `SENTRY_CLIENT_SECRET` from its process env. The verdict's `go test ./...` on Claude's branch can no longer read them. Git gets the header explicitly, and `PostAlert` takes the secret as an argument.
- **Messages.** The push-permission refusal now names the account, not the token. The timeout message reports how long the test actually waited.
- **Fix review.** `GoTest` now runs with an allowlisted env (PATH, HOME, TMPDIR, the GO* variables, SSL_CERT_*), not `os.Environ()`, so the verdict's `go test` on Claude's code doesn't inherit `GITHUB_TOKEN`, `GH_TOKEN` or `AWS_*`. HOME stays because the go command needs it, so the README says to run the test as a user whose HOME holds no credentials. This also applies to 013's `make system-test`. The allowlisted `GoTest` was vetted but not run end to end here. The timeout's reported wait is clamped at zero. The README says a repo must start with no initial commit.
